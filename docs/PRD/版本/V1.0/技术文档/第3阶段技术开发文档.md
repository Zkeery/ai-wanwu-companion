## 一、阶段目标

- **交付范围**：预置 1 个小场景 + 少量元素（雨 / 树 / 云）→ 3 个受控操作（小雨 / 安静 / 种树）→ 操作带**确认与撤销** → 对话中自然语言改变场景（LLM 识别意图 → 提议 → 确认 → 执行）→ 触发式音效 + 氛围音色 → 角色对操作作出反馈 → 场景状态持久化、重启可恢复。
- **阶段产物**：`backend/`（新增 scene 路由与模型、聊天扩展场景意图）、`static/index.html`（场景视图 + 音效 + 操作按钮）、`tests/`（扩展测试）、README 更新。
- **验收标准**：非技术用户照着点完成「打开场景 → 点『小雨』看到雨+听到雨声 → 撤销后雨停 → 聊天说『下点雨吧』→ 角色提议 → 确认后雨出现 → 刷新后场景还在」。
- **明确不做**：实时音乐生成、完整落沙/粒子物理、真实音频模型、语音、多个场景切换、场景与他人共享。

## 二、技术适配摘要

- 复用第 1/2 阶段全部代码：FastAPI + SQLite/SQLAlchemy + SSE + 单 HTML 验收页 + 统一错误结构 + `ModelClient` + 聊天/记忆。
- 本阶段启用：对话模型（场景意图识别，复用 `qwen3.8-flash`）。
- 本阶段不引入：音频生成模型（用前端 Web Audio 合成触发式音效）、完整粒子物理（用简化网格 + 少量 DOM/Canvas 元素）、正式前端、登录。
- 引用《技术适配声明》：产品仍是固定流程 C 端 AI 应用；场景操作是「确定性代码执行」，对话只是把自然语言映射到受控操作，模型不直接改场景（带确认/撤销）。

## 三、技术栈与模型

- 后端：沿用 Python 3.12 + FastAPI + SQLAlchemy + pytest。
- 对话模型：`qwen3.8-flash`（场景意图识别，走 OpenAI 兼容接口，`.env` 配置，可替换）。
- 音效：前端 **Web Audio API 合成**（白噪音雨声、氛围音色、操作短音），不引入音频文件与音频生成模型。

## 四、环境与配置

- 沿用 `.env`，**无需新增密钥或配置项**；端口 `8020`。
- 场景状态存 SQLite（沿用 `data/app.db`），跨目录启动不换数据（沿用 `config.py` 路径解析）。

## 六、数据、资产与状态

- 持久化：SQLite（沿用）。
- 数据表（新增）：
  - `scene_states`：`id`、`character_id`（外键，unique，随角色级联删除）、`state_json`（Text，JSON：元素状态 + 操作历史栈）、`updated_at`。
- 场景定义（代码常量，不入库）：
  - 预置场景「小花园」，元素：`rain`（0/1）、`tree`（0..N）、`cloud`（0/1）、`sound`（氛围音量 0..1）。
  - 受控操作 3 个（确定性代码执行）：
    - `light_rain`：`rain=1`、`cloud=1`、`sound=1`，触发雨声音效；显式点击小雨会解除此前的氛围静音，撤销恢复操作前状态
    - `quiet`：`sound=0`（氛围静音），触发静音
    - `plant_tree`：`tree += 1`，触发种树音效
- 状态机：每个操作执行前先入「操作历史栈」，撤销 = 出栈并回退该操作对元素的改动。操作历史栈也存于 `state_json`，重启可恢复（但仅支持撤销最近一次操作，MVP 单层撤销）。

## 七、API / 工具设计

统一前缀 `/api/v1`，错误统一 `{"error": {"code", "message"}}`。场景操作是即时确定性动作，不需要 SSE（直接返回新状态）。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/characters/{id}/scene` | 获取场景状态（元素 + 是否可撤销） |
| POST | `/characters/{id}/scene/actions/{action}` | 执行受控操作（`light_rain` / `quiet` / `plant_tree`），返回新状态 |
| POST | `/characters/{id}/scene/undo` | 撤销最近一次操作，返回新状态 |

**对话改变场景**：`POST /characters/{id}/chat` 的 SSE `done` 事件在原有 `message` 基础上额外附带可选 `action` 字段（`null` 或受控操作代码）。前端收到 `action` 时显示「确认 / 拒绝」；用户确认后调用上面的 `POST .../actions/{action}` 执行。模型只提议、不直接改场景。

聊天 `done` 结构：`{"message": {...}, "action": "light_rain" | "quiet" | "plant_tree" | null}`。

## 八、Prompt 设计

- **聊天场景意图**：在聊天 system 提示末尾追加规则——「当用户想改变场景（如下雨、安静、种树）时，在回复 JSON 的 `action` 字段输出受控操作代码；否则为 null。可用操作：`light_rain`（小雨）、`quiet`（安静）、`plant_tree`（种树）。不要执行，只提议。」
- 聊天输出改为 JSON：`{"reply": "...", "action": "..." | null}`，`reply` 为角色口吻的回复文本。
- **角色反馈**：操作执行后，由确定性代码选择与该操作匹配的反馈语（可用模板），或复用聊天模型生成一句；MVP 用**确定性模板**（不额外调用模型，省成本）。

## 九、验收界面或纵向切片

- 扩展 `static/index.html`：聊天面板内或独立场景面板，展示场景元素（简化 DOM/Canvas 网格）→ 三个操作按钮（小雨/安静/种树）+ 撤销按钮 → Web Audio 触发式音效 → 聊天中收到场景提议时显示「确认/拒绝」。
- 功能上限：单场景、三个操作、单层撤销、触发式音效。不做完整信息架构与视觉系统（正式前端在阶段 3 之后）。

## 十、测试要求

- 第一层 mock 测试（模型一律 mock，离线可跑）：

## 十一、验收清单

- [ ] 打开角色场景，看到「小花园」和元素默认状态

- [ ] 点「撤销」→ 雨消失、雨声停
- [ ] 点「种树」两次 → 树数量 +2；撤销一次 → 回退一棵

- [ ] 聊天说「下点雨吧」→ 角色提议「要下小雨吗」+ 出现「确认/拒绝」
- [ ] 确认后雨出现；拒绝则不变
- [ ] 刷新页面 → 场景状态仍在

## 十二、风险与待确认项

- **撤销深度**：MVP 单层撤销（只回退最近一次操作）；多层历史栈留待二期。
- **音效**：Web Audio 合成是简化方案，音色是否达标待产品经理试听后确认；不达标时二期替换为预置音频文件。
- **意图识别准确率**：LLM 把自然语言映射到 3 个操作，误识别率待真实样例验证；误识别由「确认/拒绝」兜底。
- **成本**：场景意图识别并入聊天调用，不额外增加模型调用次数。
- 必须由产品经理决定的问题：**无**（单层撤销、Web Audio 音效、3 个操作均按默认值）。
