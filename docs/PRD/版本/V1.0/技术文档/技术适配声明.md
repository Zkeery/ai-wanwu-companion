# 技术适配声明

> 项目：AI万物伙伴 · 阶段 1 技术适配 · 2026-09-18
> 配套：PRD V1.0、AI 产品 Vibe Coding 通用技术栈手册 V2.1、多项目开发指南

## 1. 产品形态判断

- **产品类型与核心任务**：固定流程 C 端 AI 应用（非 Agent Harness）。核心任务：把身边物品变成可收藏、能持续聊天的 AI 伙伴，加上声景共同活动。
- **核心交互**：分阶段确认（拍照/选图 → 识别并确认对象 → 生成角色 → 收藏 → 文字聊天 + 声景互动 → 保存 → 下次继续）。
- **开发路径**：**纵向切片（路径 B）**。理由：本产品的"角色像不像、聊不聊得下去、声景好不好玩"必须靠真实界面 + 真实模型端到端验证，纯 API JSON 无法判断质量。
- **当前阶段范围**：后端 MVP 第 1 阶段 = 照片 → 识别确认对象 → 生成角色 → 收藏 → 恢复（最小端到端链路）。

## 2. 采用的默认方案

- Python 3.12.x + FastAPI + Pydantic + pytest：手册默认后端栈，可测试、可独立验证。
- SQLite + SQLAlchemy + Alembic：多实体关系（照片/对象/角色，及后续会话/记忆），需事务与查询。
- 本地文件目录存角色图，原图临时用后删除：MVP 阶段，对象存储上线再迁。
- SSE 流式返回生成进度：角色生成是慢操作。
- 单个 HTML 静态验收页（FastAPI 挂载 `static/`）：纵向切片的最小界面，暂不引入 Next.js。
- 模型统一走配置（base_url / key / model 名），调用集中 `services` 层，Prompt 独立文件。

## 3. 触发的按需模块

| 模块 | 触发需求 | 当前阶段是否引入 |
| --- | --- | --- |
| SQLite + SQLAlchemy + Alembic | 多实体关系、事务、查询 | ✅ 是 |
| 文件存储（本地目录） | 角色图、原图临时 | ✅ 是 |
| SSE | 角色生成慢操作 | ✅ 是 |
| 视觉理解模型 | 照片对象识别 | ✅ 是 |
| 文生图模型 | 角色图生成 | ✅ 是 |
| 对话模型 | 人设 + 开场白（后续聊天） | ✅ 是（本阶段仅人设+开场白） |
| 后台任务队列 | 慢操作不阻塞 | ❌ 暂缓（SSE 同步流式够用） |

## 4. 偏离或暂缓的默认方案

| 默认方案 | 替代方案 | 原因 | 影响 | 重新评估条件 |
| --- | --- | --- | --- | --- |
| Next.js 正式前端 | 单 HTML 静态验收页 | 核心链路未验证，不铺开前端 | 界面是临时验收工具 | 阶段 3 正式前端 |
| 云数据库 / 对象存储 | SQLite + 本地文件 | MVP 单机、小规模 | 上线需迁移 | 阶段 4 上线前 |
| 任务队列 | SSE 同步流式 | 首版生成量小 | 高并发会阻塞 | 并发上来后 |
| 音频生成模型 | 静态触发式音效 | 成本高、非必需 | 无实时音乐 | 二期评估 |

## 5. 强制底线检查

- 密钥与隐私：**通过** —— `.env` + `.gitignore`，密钥只进后端配置、不回显；数据国内部署、不出境。
- 数据与任务可恢复：**通过** —— SQLite 持久化，角色/收藏/状态落库，重启可恢复。
- 输入输出校验：**通过** —— Pydantic 强校验 + 上传文件校验（格式/真实类型/大小/安全文件名）。
- 错误与日志边界：**通过** —— 统一错误 `{"error":{"code","message"}}`，不泄露堆栈，日志不记密钥/完整用户文档。
- 测试与真实模型验收：mock pytest（解析器/状态机/错误路径）+ 真实模型冒烟；**无 Key 时明确"待验"，不冒充**。
