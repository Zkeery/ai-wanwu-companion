# 第 1 阶段技术开发文档｜后端 MVP 第 1 阶段：角色生成与收藏核心链路

> 配套文档：PRD V1.0、《技术适配声明》、AI 产品 Vibe Coding 通用技术栈手册 V2.1。
> 本文档只覆盖后端 MVP 第 1 阶段，开发时不得提前实现聊天、声景、登录、付费、正式前端。

## 一、阶段目标

- **交付范围**：照片上传 → 对象识别 → 用户确认/选择对象 → 角色生成（图 + 名字 + 人设 + 开场白）→ 收藏 → 收藏列表/详情 → 服务重启后仍可恢复。
- **阶段产物**：`backend/`（FastAPI 应用）、`static/index.html`（最小验收界面）、`tests/`（mock 测试）、README。
- **验收标准**：非技术用户照着点完成"上传照片 → 选对象 → 看到角色 → 收藏 → 刷新后角色还在"。
- **明确不做**：文字聊天、声景互动、登录、付费、正式前端、跨设备同步。
- **本阶段打通的主链路片段**：照片 → 识别确认 → 生成 → 收藏 → 恢复。

## 二、技术适配摘要

- 引用《技术适配声明》结论：固定流程 C 端 AI 应用，**纵向切片**开发路径。
- 本阶段采用：FastAPI + Pydantic + SQLite/SQLAlchemy/Alembic + 本地文件 + SSE + 单 HTML 验收页。
- 本阶段启用：视觉理解模型、文生图模型、对话模型（仅人设+开场白）。
- 本阶段偏离/暂缓：正式前端、任务队列、对象存储、音频生成、完整粒子物理、Agent Harness 组件。

## 三、技术栈与模型

- 后端：Python 3.12 + FastAPI + Pydantic + SQLAlchemy + Alembic + pytest。

## 六、数据、资产与状态

- 持久化：SQLite（`data/app.db`，已 gitignore）。
- 数据表：
  - `photos`：id、filename、status、created_at
  - `objects`：id、photo_id、label、bbox_json、created_at
  - `characters`：id、object_id、name、persona、opening_line、image_path、status、created_at
- 资产：角色图存 `data/uploads/characters/`；原图临时处理、生成后删除（仅存文件名记录）。
- 状态机（character.status）：`generating → ready / failed`；object/photo 阶段用 `pending → done / failed`。所有状态落库，重启可恢复。

## 七、API / 工具设计

统一前缀 `/api/v1`，错误统一 `{"error": {"code", "message"}}`，不泄露堆栈。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/photos` | 上传照片（校验格式/类型/大小），触发识别 |
| GET | `/photos/{id}` | 返回识别出的对象列表 |
| POST | `/characters` | 选定对象生成角色，**SSE**：`chunk` 多次 → `done`（含完整角色）或 `error` |
| GET | `/characters` | 收藏列表 |
| GET | `/characters/{id}` | 角色详情 |
| DELETE | `/characters/{id}` | 删除角色（含角色图） |

SSE 约定：`chunk` 事件零到多次 → 以 `done`（含完整结果）或 `error`（统一错误结构）收尾，二者必居其一。

## 八、Prompt 设计

- `识别`：输入照片，输出对象列表（名称 + 位置），要求只识别实体物品，禁止编造。
- `人设`：输入确认后的对象特征，输出名字 + 人设（与物品特征一致）。
- `开场白`：输入人设，输出第一句话（符合角色语气）。
- 每份 Prompt 独立文件、可版本追踪；输出经 Pydantic 强校验，校验失败有限重试，仍失败走统一错误。

## 九、验收界面或纵向切片

- 本阶段需要**最小验收界面**（纵向切片）：`static/index.html` 单文件，FastAPI 直接挂载，原生 JS + fetch/SSE。
- 功能上限：上传照片 → 查看识别对象 → 选对象生成角色（流式）→ 收藏列表/详情 → 删除。不做完整信息架构与视觉系统。

## 十、测试要求

- 第一层 mock 测试（模型一律 mock，离线可跑）：
  1. 上传校验（格式/类型/大小/安全文件名）
  2. 对象识别解析器（含畸形输出、缺字段）
  3. 人设/开场白解析器（含格式不合规）
  4. 角色状态机流转（generating → ready / failed）
  5. 收藏增删查、重启后数据可恢复
  6. 错误路径（无 Key、模型超时、校验失败）返回统一错误结构
- 第二层真实冒烟（验收前）：用真实照片跑通"上传 → 识别 → 生成 → 收藏 → 恢复"，记录模型、耗时、成本、结果。

## 十一、验收清单

- [ ] 打开验收页，上传一张含"杯子/植物"的照片，能看到识别出的对象
- [ ] 选择一个对象，能看到生成进度，最终得到一个有图、有名字、有人设、有开场白的角色

- [ ] 刷新页面，角色仍在
- [ ] 删除角色后，列表不再显示
- [ ] 传一张超大/错误格式的文件，会得到明确提示而不是崩溃

## 十二、风险与待确认项

- 无真实 Key：本阶段用 mock 推进，真实效果"待验"（不得冒充通过）。

- 成本待测：角色图 + 识别 + 人设的单价与延迟待真实冒烟记录。
- 必须由产品经理决定的问题：**无**。
