# 前端第2阶段技术开发文档：照片创建伙伴

日期：2026-09-18。基线提交：fdab5a5。先完成本文，再实施。依据统一PRD、前端技术适配声明和共享前端技术栈手册；沿用现有Next.js、React、FastAPI、SQLite及单进程本地部署。用户已授权先文档后开发，本阶段不重复请求开发许可。

## 1. 本阶段目标

用户从收藏页选择一张物品或植物照片，确认或纠正对象，生成伙伴并命名，进入已有聊天页；中断后能找回服务器结果，避免误点重复生成。

## 2. 范围

包含收藏页创建入口、/companions/new三步创建页、照片校验与本地预览、对象选择与纠正、真实生成阶段提示、结果与命名、断线/刷新恢复，以及支持这些流程的后端最小补充。沿用暖白、植物绿、陶土色与现有响应式组件。

不扩展登录、付费、公开部署、跨设备草稿、角色重新绘图或新声景。生成成功即收藏，沿用现有后端事实；结果页明确已收藏，改名是独立保存，不设置假的二次收藏动作。

## 3. 用户流程

收藏页“创建伙伴”→选择图片→点击“识别照片”→选择一个对象并可编辑描述→点击“生成伙伴”→显示人设/绘图阶段→服务器ready后展示角色图、开场白与姓名→保存名字（可选）→开始聊天。

照片仅使用于识别，后端不落盘原图；前端预览URL离开时释放，sessionStorage只保存请求ID、对象ID等恢复信息，不保存图片字节。返回页后读取原任务，不自动再次识别或生成。刷新前未提交的本地文件需重选。

## 4. 页面状态矩阵

| 状态 | 页面行为 | 可执行动作 |
| --- | --- | --- |
| 未选图/本地校验失败 | 明确格式、单张10MB限制，错误贴近输入 | 重选 |
| 已选图 | 本地预览；HEIC不能预览时显示文件名和说明 | 识别/重选 |
| 上传识别中 | 不伪造百分比，显示阶段与忙碌状态，立即锁提交 | 返回收藏（只停止等待） |
| 等待对象确认 | 最多5个候选，必须选1个，描述1–100字符 | 修改描述/生成/重选 |
| 生成中 | 展示服务器SSE阶段，锁定再次生成 | 返回收藏 |
| 连接中断/刷新恢复 | 查询已存在的识别请求和对象对应角色；未知结果禁止重新付费写入 | 只读核对 |
| 服务器明确failed | 保留已确认对象与错误，不伪装收藏成功 | 用户手动重试 |
| ready | 展示服务器角色与已收藏提示，名字1–40字符 | 改名/聊天/收藏 |
| 改名结果不确定 | 保留输入、先读取角色核对，不直接重复写 | 重新核对 |

## 5. 接口契约

- 复用POST /api/v1/photos multipart file、GET /photos/{id}、POST /characters SSE、GET /characters/{id}与收藏列表。
- 照片POST增加可选Idempotency-Key（UUID）。新增持久化photo_requests表：请求ID、图片摘要、状态、photo_id。相同key同图片复用成功结果；运行中返回409；同key不同图片拒绝；失败不得用同key再次付费调用。GET /photos/requests/{key}用于只读恢复。启动时将遗留running标为failed。原无key客户端兼容。
- POST /characters新增可选label（去空白后1–100字符）；确认后的描述写入对象并用于生成人设与角色图。既有调用不传label保持兼容。
- GET /characters/by-object/{object_id}返回角色或null，供首次响应丢失后恢复。SSE增加started事件返回角色ID；保留chunk/done/error既有事件。
- 单进程创建预留锁保护同一对象重复请求的检查与落库；不在模型调用期间持锁。已有ready/generating返回409，failed允许用户明确重试。
- PATCH /characters/{id}接受name（去空白后1–40字符），仅ready可修改；返回完整角色，并同步开场白中明确自称的名字；不改变人设或已保存聊天历史。
- 后端沿用统一error envelope。图片类型继续由服务器嗅探，原图不保存；客户端不伪造HEIC预览。现有上传接口未严格验证解码像素尺寸，4096长边目标不作为本轮已实现事实，独立列入图像输入后续加固项。

## 6. 实现方案与顺序

1. 本文落地并写入项目状态；随后补齐后端请求恢复、对象纠正和改名契约及测试。
2. API与类型适配集中放lib；生成流独立解析器覆盖拆包、错误、缺少done、非法状态，不影响既有聊天流。
3. 创建页使用局部状态、同步互斥ref和AbortController；请求超时只停止等待。sessionStorage写入恢复ID失败时阻止付费请求并提示，避免失去恢复依据。读取失败保持恢复态，不自动重发。
4. 复用收藏与详情；成功后进入/companions/{id}，刷新以服务器为准。
5. 完成定向测试、lint、类型、build和浏览器桌面/手机验收；记录证据后才报告本阶段结果。

## 8. 风险与回退

既有生成与连接生命周期绑定；停止等待不能承诺取消收费任务。恢复查询遇到generating只继续查询；旧进程异常退出由现有启动恢复标failed。请求恢复表采用新增表，不改变现有数据列；创建预留锁只支持既定单进程，扩容需数据库唯一约束与任务队列。失败/未使用的识别元数据仅含文件名、摘要与对象文字，不含原图。保留旧8020页面作为本地回退入口。
