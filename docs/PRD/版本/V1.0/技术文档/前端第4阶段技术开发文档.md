# 前端第 4 阶段技术开发文档：生成速度与等待恢复

2026-09-19；基线提交 `2d93d3c`。先编写本文，再按本文实施与验收。

## 1. 目标与证据

PRD 要求确认对象后生成等待目标 ≤30 秒。第 2 阶段唯一成功真实样例耗时 31.429 秒：人设约 10.271 秒、开场白约 4.901 秒、绘图约 16.257 秒，当前三步串行。此结果不是平均值或 P95。

本阶段只优化生成编排与相应等待提示。人设返回名字后，开场白仅依赖名字/人设，绘图仅依赖对象描述/名字，二者可并行。预计耗时由 `人设 + 开场白 + 绘图` 变为 `人设 + max(开场白, 绘图)`；按旧样例计算约 26.5 秒，**仅是推算，真实达标必须重新实测**。

不更换模型或 Prompt，不减少返回质量校验，不引入后台任务系统，不开展登录、额度、部署或下一阶段功能。

## 2. 实现方案

- ModelClient 提供 `generate_persona(label)`、`generate_opening(persona)`；保留原 `generate_character(label)` 包装方法供现有调用者兼容。原有模型名、Prompt、temperature、HTTP 超时与重试配置不变。
- API 先生成并校验 Persona，然后提交两个独立线程任务：开场白和绘图。每次创建最多两个并行任务；线程中不共享数据库 Session，每个 HTTP 调用仍使用自己的 Client。
- 只在两项成功且开场白解析通过后写入完整角色并置为 ready；失败时回滚并置为 failed。前置人设失败时，不发起开场白/绘图。
- 并行失败有代价：开场白失败时绘图可能已经开始并产生费用。失败路径必须等待已启动任务结束，清理已生成但未归档的图片；不能把 Future.cancel 当成已取消上游请求。单次成功路径调用数仍为文本 2 次、图片 1 次，失败重试沿用现有显式用户操作。
- 图片清理逻辑抽到共享服务，保留上传根目录限制和历史共享路径保护。任何角色删除、数据库写入失败、连接关闭不得留下可识别的未归档图片；测试覆盖晚返回图片。
- 角色预留仍在模型调用之前持久化，沿用单实例创建锁；同对象正在生成/已完成时返回 409。进程重启仍将残留 generating 标记 failed，允许用户核对后手动重试。
- 真实 TCP 测试发现同步 SSE 生成器的回收时机不稳定，不能依赖垃圾回收触发 finally。响应退出时，在受取消保护的清理块内显式关闭生成器；若生成器尚未开始，也要把本次预留的 generating 记录置为 failed。等待正在运行的线程完成后再清理，不中止上游 HTTP 调用。

## 3. API 与页面契约

`POST /api/v1/characters` 的请求、响应格式和 SSE 事件名不变：started → chunk → chunk → done 或 error。

阶段提示依次为“正在生成人设…”和“正在准备开场白和角色图…”。不再显示与实际并行顺序不符的串行绘图提示，不显示虚假百分比或保证 30 秒完成。

浏览器验收确认 Next.js 代理的 gzip 会缓冲小型 SSE 分块。生成响应增加 `Cache-Control: no-cache, no-transform` 和 `X-Accel-Buffering: no`，保持事件即时到达；用带 gzip 请求头的真实代理请求对照验证。

刷新/离开仅停止浏览器等待，不主动重发 POST；回到创建页通过已持久化 ID 核对 generating / ready / failed。若断开导致流程未完成，应能读到 failed 并手动重试；若任务已完成则恢复 ready。等待提示改为“离开后可回来核对结果；状态未确认前不会自动重复生成”，避免暗示所有断开场景都一定在后台完成。

错误继续使用 `{error:{code,message}}`；不返回服务商正文或堆栈。数据 schema 与已有客户端兼容。

## 4. 验收标准

| 维度 | 必须验证 |
| --- | --- |
| 并行依赖 | 人设先完成；开场白与绘图均已进入执行后才释放测试屏障；输入名字一致 |
| 调用与失败 | 人设失败零下游；开场白失败/超时且图片晚到时清理；绘图失败时不 ready；无新增自动重试 |
| 状态与并发 | 重复提交仅一个创建者；并行时 GET 不阻塞；生成中删除不复活；失败后可手动重试 |
| 断线 | 本地真实 HTTP/SSE 断开、等待结束及重新查询状态；无永久 generating 或孤立图片；不把普通 TestClient 缓冲响应当成断线验证 |
| 性能 | 离线固定延迟对照验证执行重叠；真实样例从 POST 发出到 done 接收计时，成功且 ≤30 秒才标记该样例达标 |
| 工程 | 后端/前端/旧页面回归、lint/typecheck/build；Chrome 桌面/手机实际阶段提示、离开返回恢复；原数据与密钥排除 |

真实耗时受服务商负载影响；一次通过仅关闭本次性能冒烟，不能据此宣布长期 P95 达标。若真实实测超过 30 秒，保留原始结果并继续定位，不调宽阈值。
