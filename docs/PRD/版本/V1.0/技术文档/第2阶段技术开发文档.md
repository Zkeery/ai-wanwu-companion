# 第 2 阶段技术开发文档｜后端 MVP 第 2 阶段：文字聊天 + 会话保存恢复 + 手动记忆

> 配套文档：PRD V1.0、《技术适配声明》、《第 1 阶段技术开发文档》、AI 产品 Vibe Coding 通用技术栈手册 V2.1。
> 本文档只覆盖后端 MVP 第 2 阶段，开发时不得提前实现声景互动、场景、音效、登录、付费、正式前端。

## 一、阶段目标

- **交付范围**：对已收藏角色发起持续文字聊天（SSE 流式回复）→ 聊天历史持久化并在重启后恢复 → 用户手动标记少量记忆（增/查/改/删）→ 聊天时把记忆注入上下文 → 历史与记忆的删除控制（删除即生效）。
- **阶段产物**：`backend/`（新增 chat/memory 路由与模型）、`static/index.html`（扩展聊天与记忆界面）、`tests/`（扩展测试）、README 更新。
- **验收标准**：非技术用户照着点完成「选角色 → 发消息 → 收到符合角色语气的回复 → 刷新后聊天记录仍在 → 标记一条记忆 → 查看/纠正/删除记忆」。
- **明确不做**：声景互动、场景与音效、登录、付费、正式前端、跨设备同步、自动记忆提取（长期记忆不做全量提取，仅手动标记）。

## 二、技术适配摘要

- 复用第 1 阶段全部结论与代码：FastAPI + Pydantic + SQLite/SQLAlchemy + SSE + 单 HTML 验收页 + 统一错误结构 + `ModelClient`。
- 本阶段启用：对话模型（持续聊天，复用第 1 阶段 `qwen3.8-flash`，走 OpenAI 兼容 `/chat/completions`）。
- 本阶段不引入：向量检索 / RAG（记忆是少量手动词条，不做语义召回）、后台任务队列（聊天用 SSE 同步流式足够）、正式前端、登录。
- 引用《技术适配声明》：产品仍是固定流程 C 端 AI 应用，聊天是「固定编排」中的一步，不引入 Agent Harness 组件。

## 三、技术栈与模型

- 后端：沿用 Python 3.12 + FastAPI + SQLAlchemy + pytest。
- 对话模型：默认 `qwen3.8-flash`（蚂蚁数字 MaaS，`.env` 配置，可替换）。模型名、base_url、超时、重试全部走配置，代码不硬编码。

## 四、环境与配置

- 沿用第 1 阶段 `.env`，**无需新增密钥或配置项**；启动端口 `8020`。
- 数据库与上传目录继续由 `config.py` 相对 `backend` 目录解析，跨目录启动不换数据。

## 六、数据、资产与状态

- 持久化：SQLite（沿用 `data/app.db`）。
- 数据表（新增，均含 `created_at`）：
  - `messages`：`id`、`character_id`（外键）、`role`（user / assistant）、`content`、`created_at`。一个角色一个会话，消息按 `character_id + created_at` 查询即为其历史。
  - `memories`：`id`、`character_id`（外键）、`content`、`created_at`、`updated_at`。用户手动标记的少量记忆。
- 关系与约束：
  - 消息、记忆随角色删除而级联删除（外键 `ondelete=CASCADE`，删除角色时清理其全部会话与记忆）。
  - 聊天历史与记忆均归属角色；MVP 单机单用户，暂不做用户维度的隔离（登录在后续阶段）。
- 状态机：聊天无需额外状态机；消息一旦落库即视为已保存（先存用户消息，再流式生成回复并保存）。

## 七、API / 工具设计

统一前缀 `/api/v1`，错误统一 `{"error": {"code", "message"}}`，不泄露堆栈。SSE 必须以 `done` 或 `error` 收尾。

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/characters/{id}/chat` | 发送消息，**SSE**：先存用户消息 → `chunk` 流式输出回复 → `done`（含完整回复与消息 id）或 `error`；聊天中断时已保存的用户消息不丢失 |
| GET | `/characters/{id}/messages` | 聊天历史（按时间升序） |
| DELETE | `/characters/{id}/messages` | 清空该角色聊天历史 |
| POST | `/characters/{id}/memories` | 手动标记一条记忆 |
| GET | `/characters/{id}/memories` | 记忆列表 |
| PUT | `/memories/{id}` | 纠正一条记忆 |
| DELETE | `/memories/{id}` | 删除一条记忆（删除即生效） |

SSE 约定：`chunk`（回复片段，零到多次）→ 以 `done`（含完整回复）或 `error` 收尾，二者必居其一。

## 八、Prompt 设计

- **聊天 system 提示**：固定角色身份——「你是用户的 AI 伙伴，名字 X，人设 Y。用与人物一致的语气自然对话，不跳出角色，不承认自己是模型。」
- **聊天上下文**：`system 提示（含名字+人设）` + `手动记忆（若有，逐条作为「你记得的事实」）` + `最近 N 条历史消息` + `用户当前消息`。
- **记忆注入**：把该角色全部手动记忆作为稳定事实注入 system，让角色「记得」；记忆条数少（MVP 上限建议 20 条），不需要向量检索。
- **历史截断**：取最近 N 条（默认 20 条）避免超上下文窗口；超出部分只做持久化、不进本轮上下文。
- Prompt 模板独立文件、可版本追踪；输出经结构校验，校验失败有限重试，仍失败走统一错误。

## 九、验收界面或纵向切片

- 扩展 `static/index.html`：收藏列表点击角色 → 聊天视图（历史消息 + 输入框 + 流式回复 + 断流/错误提示）→ 记忆区（新增/查看/纠正/删除）→ 清空历史按钮。
- 功能上限：选角色 → 聊天 → 刷新后历史仍在 → 标记/纠正/删除记忆。不做完整信息架构与视觉系统（正式前端在阶段 3）。

## 十、测试要求

- 第一层 mock 测试（模型一律 mock，离线可跑）：
  1. 聊天 SSE：先存用户消息、`chunk`/`done` 顺序与收尾正确
  2. 消息持久化 + 重启后历史可恢复
  3. 记忆增/查/改/删 + 删除角色时级联清理
  4. 上下文拼接：system 含人设、记忆被注入、历史按最近 N 条截断
  5. 清空历史、删除记忆后即时生效
  6. 错误路径：角色不存在、模型超时/失败、SSE 中断不丢已保存用户消息，均返回统一错误结构
- 第二层真实冒烟（验收前）：用真实对话模型聊 5–10 条，记录模型、耗时、成本、语气一致性；**并对这 5–10 条真实样例打分定质量门槛（PRD 第 4 节）**。

## 十一、验收清单

- [ ] 打开验收页，选一个已收藏角色，发一句话，收到符合该角色语气/人设的回复
- [ ] 回复是流式出现的，结束后能看到完整回复
- [ ] 刷新页面，聊天记录仍在
- [ ] 标记一条记忆（如「我喜欢下雨天」），列表中能看到
- [ ] 纠正这条记忆，内容更新；删除这条记忆，列表不再显示
- [ ] 新发一条消息，角色能「记得」已标记的记忆（回答中体现）
- [ ] 清空历史后，聊天记录不再显示
- [ ] 断网/超时场景下，已发送的用户消息不丢失，且得到明确提示而非卡死

## 十二、风险与待确认项

- **上下文窗口**：历史取最近 N 条（默认 20），超长对话的早期内容不进本轮上下文（仍持久化）。
- **成本**：每轮聊天消耗 token；历史越长，单轮上下文越大。MVP 用最近 N 条截断控制成本，具体 N 与单用户成本待真实冒烟记录。
- **记忆上限**：MVP 建议 20 条/角色；是否给上限或提示由真实样例打分阶段决定。
- **质量门槛**：PRD 第 4 节「数字门槛」在本阶段真实冒烟时用 5–10 条样例打分后定，仍不阻塞开发。
- 必须由产品经理决定的问题：**无**（N 值、记忆上限均按默认值，标注理由即可）。
