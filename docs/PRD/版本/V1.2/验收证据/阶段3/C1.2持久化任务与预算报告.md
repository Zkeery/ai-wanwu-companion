# C1.2：持久化任务、授权与费用预留

日期：2026-09-23。依据PRD 10.5、10.9、10.10；前后端第3阶段手册第11／10节先于实现更新。本增量为独立后端内核，C1私人自主生活整体仍未完成。

## 这次完成了什么

`LifeRuntime`将授权、任务、租约、单步活动状态变更、回执和费用预留保存到SQLite。暂停或重新授权会取消旧任务；重启后可以发现未结束任务、接管过期租约，旧执行者不能再提交。重复请求只留下一个事件，执行失败会完整回滚。

预算同时受项目和空间限额限制，默认均为0，每任务最多2次调用预留。重复调用标识不再获得发送许可；失败费用未知时仍占用预留，暂停、重启或租约过期均不释放。迟到的确定账单可在任务结束后结算。

**当前数据全部明确标注为`offline_fixture`。** 本轮调用网络次数0、真实模型费用0；测试中的微元额度是合成账本数据。执行仅改变隔离内核的活动状态，不代表角色实际移动、自然对话或形成真实AI生活经历。主应用尚未接入这些表、接口或页面，主库没有迁移，旧用户生活记录没有加入离线事件。

## 可核对结果

| 操作或异常 | 实际结果 |
| --- | --- |
| 尚未授权就排队；预算为0就申请调用 | 均拒绝；没有事件或费用预留 |
| 保存许可→排队→暂停→重放旧保存请求 | 旧任务取消，许可保持暂停，不被旧回执重新开启 |
| 两个线程同时排队、领取、提交 | 同一请求返回同一任务；租约只有一个获胜者；最终只有一个事件 |
| 租约过期后被新进程接管 | 生成新令牌，旧令牌提交被拒绝 |
| 伙伴离开后返回、场景或授权变化 | 原任务取消，无虚构事件 |
| 21:59排队，22:00执行散步 | 执行被拒绝；夜间获准休息可通过 |
| 模型候选越权或观察不存在物件 | 保存failed回执，不创建事件 |
| 事件写入后故意制造回执保存失败 | 事务回滚，事件数0，任务仍可安全重试 |
| 取消任务时存储失败 | 授权与任务同时回滚，状态不分裂 |
| 离线任务失败／取消、服务一天未运行 | 仍受每日2次和600秒间隔约束，不补写历史经历 |
| 两个调用同时争用额度 | 只有符合剩余额度的一次获准，未超额；不同空间共用项目总上限 |
| 调用费用未知后重启、重复call_id | 全额继续预留，重复call_id返回不允许再次发送 |
| 任务结束后到账、重复结算 | 可保存确定金额；同一结算幂等，修改已结算结果被拒绝 |
| 跨账号、错任务、损坏授权／任务／账本／事件 | 拒绝访问或失败关闭，不静默恢复成成功 |
| SQLite备份→恢复到独立文件 | 授权、任务、事件及未知费用一致，恢复库更改不影响原库 |

## 真正跨进程的恢复验证

第一个独立Python进程排队、领取任务并预留30微元合成额度，然后完全退出。第二个进程只获得数据库路径、主人和空间，不接收任务ID；它从存档发现任务，租约到期后重新领取，提交活动状态，再重复提交。

实际检查结果：任务done、事件总数1、两次提交回执相同、令牌已更换，30微元未知费用仍在。这是内核的真实存储与进程恢复验证；候选文本和额度是离线合成数据，不是模型效果验收。
