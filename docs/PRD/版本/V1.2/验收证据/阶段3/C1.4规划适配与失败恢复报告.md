## 已验证的结果

| 场景 | 实际离线验证结果 |
| --- | --- |
| 正常散步／观察 | 一次请求、一次单步事件，事件仍标offline_fixture |
| 夜间活动 | 休息可通过；散步被执行器拒绝 |
| 不合规输出 | 非JSON、围栏、数组、空值、重复键、NaN、额外字段、非法活动、空／超长／多行解释、超大响应均失败，无完成事件 |
| 目标不存在 | 不接受模型编造的目标ID |
| 费用不足 | 客户端不初始化、不派发请求 |
| 本地客户端初始化失败 | 任务失败，费用预留按0结算，不回显异常正文 |
| 初始化期间暂停 | 请求发出前再次检查许可，零请求、原任务取消 |
| 请求异常／超时／异步取消 | 保留未知费用，不自动重试，不使用预设活动冒充成功 |
| 收到响应前暂停或改变场景 | 不执行过期候选，原任务取消 |
| 收到响应时租约过期 | 旧工作器不能提交，接管时不重复请求 |
| 两个并发工作器 | 只有一个获得租约并发出请求 |
| 预留后中断／结果未知后重开数据库 | 固定调用ID禁止再次派发，保留原费用预留，任务失败关闭 |
| 响应后账本保存失败 | 保留reserved记录及未完成任务，不造事件 |
| 错主人／租约 | 读取规划输入时拒绝 |

正常响应也不代表已知账单，所以测试中预留30个合成微元仍为unknown；它不是人民币支出或供应商账单。数据库重开验证创建了新SQLAlchemy engine并从SQLite恢复；本轮不声称已做真实供应商进程故障恢复。

规划请求只包含场景、季节、天气、上海时间、获准活动和可见物件ID／类型。测试核对了字段集合及身份排除；主人、空间、伙伴身份、租约、账本、聊天和记忆不进入请求。原始输出及异常文本不保存为用户事件。候选最多4096字节，等待上限15秒，每任务最多一次请求、零自动重试。
