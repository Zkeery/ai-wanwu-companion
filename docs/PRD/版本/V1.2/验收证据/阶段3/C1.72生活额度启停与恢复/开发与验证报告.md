# C1.72 生活额度启停与恢复

2026-10-01。本轮补齐自主生活正式运行后的额度维护流程，工程与离线恢复验证通过。没有新增真实调用或费用，没有发布，也未开启本人自主生活。

## 完成的流程

对应PRD10.5、10.9，先补齐前后端第3阶段技术文档，再实现以下闭环：

1. 显式选已有数据库、主人和私人空间，生成只读方案。SQLite以ro打开，不建库、不建表、不修改额度。
2. 核对累计项目上限、累计空间上限和已用／未知预留。方案摘要绑定当前账目、目标金额及操作类型；变更金额或账目变化后，旧摘要不能继续提交。
3. 获本次具体费用授权后，显式apply并提供请求ID、授权记录编号和原方案摘要。两个上限及回执一次事务提交，中途失败全部回滚。
4. 关闭本空间剩余额度时，将空间上限降至其已用及未知预留之和。项目上限与其他空间不变，未知费用不返还，也不声称能撤回已派发的供应商请求。
5. 重启后再次提交同一请求，只读取原回执。即使后来已收回额度，也不会重放旧请求重新放开；旧授权编号不能换一个请求ID再次使用。

维护入口是`backend/scripts/manage_life_budget.py`，没有新增HTTP接口或模型工具。命令不发放用户活动许可，不开启每日安排／观看模式，不直接派发或重试任务。关闭剩余额度是停止后续可预留调用；需要暂停活动时仍使用既有用户暂停按钮，两者含义保持明确。

新表`life_runtime_budget_changes`由已有运行库初始化过程创建。旧库仍可只读预览，但缺回执表时明确拒绝apply，不能趁维护操作静默迁移。旧c16试用命令保留原固定测试目标和兼容行为；正式库维护应使用新命令，本轮不宣称旧命令已具备新回执协议。共用金额解析新增极大指数兜底，避免非法金额导致堆栈输出。

## 复核命令与操作约束

在项目`backend/`运行：

```sh
.venv/bin/python -m pytest tests/test_life_budget_admin.py tests/test_life_runtime.py tests/test_life_live_planner.py tests/test_life_live_automatic.py tests/test_life_automatic.py tests/test_life_viewing.py tests/test_life_dispatch.py tests/test_life_formal_runtime.py tests/test_full_flow_restore.py -q
```

只读方案格式如下。数据库必须为已有文件的绝对路径，主人和空间须匹配；金额是累计上限，不是本次追加金额。若已有保守占用，新批次上限需把原占用一起计算，不能用新金额覆盖未知费用。

```sh
.venv/bin/python -m scripts.manage_life_budget --database <已有库绝对路径> --owner-id <本人ID> --space-id <私人空间ID> --project-yuan <项目累计上限> --space-yuan <空间累计上限>
.venv/bin/python -m scripts.manage_life_budget --database <已有库绝对路径> --owner-id <本人ID> --space-id <私人空间ID> --freeze-space
```

返回的金额单位为`micro_yuan`，1000000等于1元。只读输出的`expected_state`用于绑定本次方案；真正保存另需明确`--apply --expected-state <原摘要> --request-id <新UUID> --authorization-ref <本次授权编号>`，并保留同一目标、操作和金额。授权编号为8–120个英文字母／数字或`_.:/-`，不填密钥。模型、浏览器和普通用户请求都没有此维护入口。

`state=replayed`且`receipt_only=true`表示历史回执，不是当前额度；用新的只读预览核对当前金额。无需为重试生成新请求ID，同一请求即可安全核对未知提交结果。不得用历史收费授权重复发放新额度。
