## 启动与维护

在本项目 `backend/` 运行：

```bash
.venv/bin/python -m scripts.check_candidate_review seed-pending
.venv/bin/python -m scripts.check_candidate_review serve
.venv/bin/python -m scripts.check_candidate_review pending-status
```

`serve` 持续运行，其他命令另开终端执行。前端沿用 C1.60 启动方式，端口 3050、后端 8048；详见 [C1.60 报告](../C1.60产品内候选确认/开发与验证报告.md)。不要同时启动两个 8048 服务。

正式配置初始化数据库后，维护入口默认只读：

```bash
.venv/bin/python -m scripts.motion_generation_request plan --character-id <伙伴ID> --owner-id <本人ID>
.venv/bin/python -m scripts.motion_generation_request status --character-id <伙伴ID> --owner-id <本人ID>
```

只有获得针对新任务的明确费用授权后，才使用 `grant` 的 request-id、source-sha256、approval-ref、price-verified-on、accept-metered-cost 参数保存授权；`MOTION_GENERATION_ENABLED=true` 才允许工作进程消费。单次授权限制请求次数，不能替代供应商账户的金额上限。本轮没有执行 grant，也没有启用生成。异常未知任务只核对已有回执，不重新入队。

新增 `motion_generation_requests` 表由现有启动建表流程创建；不改已有表结构。回退时关闭生成开关并保留新表和供应商回执，无须删除任务数据。当前沿用单服务进程部署；扩成多进程部署前须调整启动恢复的归属规则。
