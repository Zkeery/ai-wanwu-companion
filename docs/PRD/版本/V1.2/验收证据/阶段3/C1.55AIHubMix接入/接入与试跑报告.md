## 2026-09-29 403 原因定位

新增两次缺少必填 prompt、没有图片的无效请求，用于读取网关拒绝原因；不是有效生图重试。平台均返回 HTTP403，原始错误码 `async_not_enabled`，明确要求去 `/async-tasks` 开通。第二次显式 `async:false`，仍然被同一开关拦截，证明当前同步原生入口也受该账户功能门槛限制。与昨日真实调用使用相同 Key、模型和接口；结合控制台未开通状态，可将当前访问阻断定位到异步任务未启用，昨日原始错误正文未保留，不能声称恢复了昨日正文。

控制台 Async Tasks 页面显示 `Enable async tasks`，说明启用须阅读并接受 `Async Data-Storage Agreement`。本次仅打开页面，未启用、未接受协议。官方文档将 `async_not_enabled` 定义为账户未开启异步任务；同步调用同样受限是本次实测发现。

此前适配器将全部403映射为 `provider_access_denied`，丢失了更具体的供应商错误码，导致初次未能定位。后续修复应对白名单错误码保留区别，不能把全部403等同于Key权限错误。下一步为确认数据存储协议后启用该功能，再做无效请求校验；新一张收费试跑仍需单次授权。详见[同步模式诊断](403同步模式诊断.json)。
