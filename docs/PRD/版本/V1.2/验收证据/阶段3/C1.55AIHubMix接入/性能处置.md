# C1.55 性能处置

2026-09-29。当前Sunburst medium四姿态路线不具备进入实时动作链路的验收依据，45.097秒已直接超过动画准备10秒上限。本次调用从既有伙伴图生成四姿态，仅测维护脚本请求到候选保存／基础检查；没有测用户上传原照片到首次伙伴形象展示，因此不能把45秒写成首次生图8秒的实测值。首次生图仍独立待验。

当前执行重点回到性能阻断：不再把继续制包、绑定或页面联调当成解决速度问题；保留成功候选供质量比较。下一次测速先增加POST请求往返、结果下载、校验／制包、前端显示的分段时间；POST耗时是网络与供应商处理的合计，不能直接断言全部属于模型推理。无有效分段数据，不承诺换通道或并发可提速到10秒。

首个候选为同平台GPT Image 2.5 Flare。2026-09-29官方模型页标为更快的图片模型；原生逐模型Schema确认支持参考图、medium、1024规格及透明PNG。这只是筛选依据，没有当前项目实测速率承诺，尚未变更专用Key模型权限或正式模型。对照保持同一原图、提示和画质，先1张测速度／质量；自身超10秒即停止该路线追加同设置请求。首张通过也仅进入下一轮端到端验证，按PRD每次上传开始→图片展示≤8秒、图片展示→动画可用≤10秒分别验收；任一样本超限记失败，不剔除慢样本，不拿缓存命中或异步接单充当首次达标。

若更快路线仍不满足速度与质量，说明该即时生成架构尚不可交付；须形成有实测证据的其他实现方案或明确的需求调整，再由用户决策。禁止默默放宽时限、降低形象或动作标准。后续真实费用及模型权限变更须具体确认，本轮未发模型请求。

依据：[Flare模型页](https://aihubmix.com/model/gpt-image-2.5-flare)、[逐模型Schema](https://aihubmix.com/call/schema/models/gpt-image-2.5-flare/endpoints)、本项目PRD第5.3与9.3节。
