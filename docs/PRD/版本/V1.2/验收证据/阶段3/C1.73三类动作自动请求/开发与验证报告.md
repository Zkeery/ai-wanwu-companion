# C1.73 新伙伴三类动作自动请求

2026-10-01：工程链路已接通并更新本机体验服务，真实新伙伴三类生成仍待验。本轮真实模型、短信、云部署均为0，不宣布第3阶段或V1.2全部完成。

对应PRD第4节生成联动、10.4活动呈现、10.5自主活动，以及2026-09-29用户确认的休息／观察含义。新伙伴形象保存成功时，在同一事务登记休息、散步、观察三个任务。获得明确的一次性批次授权后，后台逐类生成候选；用户审图接受后制包、绑定并播放，刷新及重启可恢复。旧散步接口与表保留。已有散步就绪时，其他两类待办仍显示。

浏览器的“准备三类动作”只登记免费任务，不授予收费权限。维护端grant-all在一个事务中登记三个不同引用；并发worker不能同时处理同一批，技术失败／结果未知／进程中断停止未开始的请求，不自动重试或追加额度。三类候选均保留人工确认，不能用技术校验替代视觉质量判断。

## 用户核对

打开现有[伙伴页面](http://127.0.0.1:3050/)，进入一个伙伴，点放大形象，再切换休息／散步／观察。已有动作可以播放；没有动作时查看对应准备进度。“准备三类动作”只保存任务；没有新的收费授权就不会生成。打开“查看待确认动作”，按分类核对候选，接受后才绑定；刷新可重新读取保存状态。

本轮合成伙伴已清理，所以截图中的伙伴不会出现在本人收藏中。本人原有伙伴及此前真实验收记录保留；新伙伴真实批次见[具体方案](真实三类动作验收方案.md)。

## 开发者复验入口

在backend运行`.venv/bin/python -m pytest -q tests/test_motion_generation.py tests/test_motion_generation_activities.py`；在frontend运行`npm test -- tests/motion-generation-activities.test.ts tests/motion-generation-status.test.tsx`。完整相关测试文件集合见[验证结果](验证结果.json)，不是全项目测试通过声明。

新接口为`GET/POST /api/v1/characters/{id}/motion-generation/activities`，POST仅接受`{}`，固定rest／walk／observe顺序，private,no-store；错误仍为统一error结构。模型授权只在可信CLI执行：`python -m scripts.motion_generation_request plan --character-id ID --owner-id OWNER --activity rest`默认只读。grant-all要求已确认source SHA、当前日期、独立approval_ref和显式费用许可；普通页面没有对应授权API。

隔离复现入口为`python -m scripts.check_three_activity_flow prepare|build|start|advance|proof|stop|verify-artifacts|cleanup`，advance明确选activity且只使用禁外网合成provider。prepare要求新空目录，不覆盖此前回执；已finished目录需由开发者先归档回执再另行准备。本人维护入口update_three_activity_review为本轮一次性操作，已有备份／回执时拒绝重复运行。
