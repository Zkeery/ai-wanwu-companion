# C0：四个可审阅的生活样例

日期：2026-09-23。依据PRD第10.3–10.5、10.7、10.9、10.10节。本页是**规则样例**，不是已发生的角色生活、真实模型输出或已上线页面。现有R3.2模拟面板只覆盖私人休息、散步、观察，R3.3/R3.4记录的是用户手动操作。

2026-09-23产品判断：用户回复“按推荐”，四个样例确认为开发验收基线；允许进入C1不产生模型费用的工程增量。具体收费试跑预算仍未授权。

## 样例一：私人一天

主人为已有杯子伙伴在私人庭院开启“休息、散步、观察”，没有授权照料和天气变化。白天进入时，系统读到伙伴仍在家、庭院有一棵可见小树、距上轮已过10分钟；候选计划“观察小树”经授权、目标和版本校验后，才可留下来源为“伙伴自主行动”的真实事件。主人能看到“观察了哪棵树、依据是什么、下一步待安排”。若小树被收纳或主人暂停，旧计划作废，不能留下已观察记录。22:00以后只可休息；即使无人打开页面，也不能补写未运行时段的对话。

**需主人介入**：开启及活动范围选择；若想让它照料植物，另行允许无消耗照料。**失败显示**：没有目标时“今天没有可观察的物件”，保留手动布置入口，不编造植物。

## 样例二：自己的伙伴同住

同一主人让杯子与植物伙伴住在已存在的共同私人场景。主人分别允许两位伙伴参与，不把一个伙伴的许可复制给另一个。两者都在场且白天时，可提出“杯子靠近长椅，植物伙伴一起观察小树”的有限计划；执行前再次核对两位伙伴位置及场景版本，只保存实际完成的一步和参与者。主人随后召回植物伙伴，则未执行的交流步骤失效；两个角色不在两处同时行动。此样例在第3阶段验证同账号关系，不代表跨账号小队功能已完成。

**需主人介入**：选择参与伙伴、可执行活动；布置或改变场景仍按原确认规则。**失败显示**：同伴离开时说明已无法一起活动，不生成对话。

## 样例三：合作种树

两个已获各自主人许可的伙伴到同一小队空间。成员主动开启“布置休息角落”目标后，伙伴可建议种树和摆长椅；添加物件仍须由有权限者确认，或使用事先限定目标、区域、数量的授权。树、长椅、贡献者与24小时照料窗口以真实存档判定。树木约72小时**有效成长**成熟，漏照料只暂停，不死亡，也不靠连续点击加速。成员退出、权限撤销或任务版本变化时，排队步骤作废；不能移走他人贡献。该样例属于后续第4阶段，不作为本轮已实现功能。

**需成员介入**：主动开启目标、确认布置授权和伙伴参与。**失败显示**：没有树或长椅时保持“进行中／等待补齐”，模型台词不能宣布目标完成。

## 样例四：温和分歧与回家

两位伙伴对庭院安静／热闹有轻微不同偏好，且双方主人都允许关系故事。系统可让双方简短表达、尝试协商；仍想独处的一位在安全结束当前步骤后回自己私人住处。主人看到去向，不会在小队与家里同时执行。独处一段时间后可恢复平静并再次相聚；关闭关系故事后不再发起新分歧，已有独处仍能自然结束。不得辱骂主人、强迫用户安慰、伤害植物、删除物件或让他人的任务失败。本例是第4阶段的规则审查，不是当前界面已具备情绪识别。

**需主人介入**：分别允许参与和自主回家；主人可选择安慰、邀请或让它独处。**失败显示**：原住处已明确删除时提示重新选家，不擅自新建住处。

## 跨样例核对

| 核对点 | 必须成立 |
| --- | --- |
| 事实来源 | 用户、模拟、真实伙伴行动和成长结算分别标来源；没有回执就没有“已做”事件 |
| 许可 | 每个主人只管自己的伙伴；方案和执行两次核验；删除、公开、邀请与付费生成始终人工确认 |
| 时间和费用 | 有人看最多10分钟一轮、无人看每日最多2轮均为上限；没有具体C1预算就不调用模型 |
| 中断与恢复 | 暂停、离开、版本冲突、模型失败不补造结果；请求ID幂等，服务重启后读取持久化状态 |
| 身份与画面 | 同一伙伴身份、位置、活动和动作一致；缺动态资源仍显示静态伙伴，不把整图摆动写成角色动作 |
