# C1.43 生成后动作准备：开发与验证

2026-09-28。对应PRD 10.13，开发前先补前后端第3阶段技术文档。本批已接通生成成功登记任务、本地分类包提交、后台校验与私有绑定；**尚未实现任意新图自动生成合格动作素材**。没有素材时状态为waiting_source，不会假报ready。角色图片不等待动作处理。

## 实现与验证

- 生成ready与三类任务同事务提交；登记不读媒体、不调用模型。失败整体回滚，重复登记幂等。
- 本地包按本人、伙伴、原图摘要和活动匹配；CLI默认dry-run，显式apply后排队。异包拒绝覆盖；失败任务可显式提交修正包。素材语义仍需人工审查。
- 后台每2秒消费，每批最多3条，校验与绑定／终态在同一SQLite写事务；损坏素材最多3次，改图／换归属立即失败，中断回滚后重启可继续。
- 新增本人只读准备状态接口；原有素材接口与前端播放器协议不变。角色删除级联任务，未处理包和已绑定包进入同一恢复清理流程。清理先排除引用再限量，避免在用素材阻塞删除队列。

后端全量 **1415/1415**，其中新增17项；只有原有两条依赖弃用提示。覆盖生成回滚、后台启动、三类素材、并发消费者、复制中改图、跨账号、资源损坏、有限重试、终态复核、删除及恢复。前端代码未改，本批无需重跑前端构建；C1.42的前端结果不冒充本批新增测试。

另外用C1.38已归档三份候选包和苹果原图，在全新临时数据库与上传目录跑两个独立Python进程的实际FastAPI生命周期：三类任务均waiting_source→queued→ready，均仅处理一次，六个私有媒体读取成功；重启前后元数据、资源标识与任务状态一致，SQLite备份恢复任务行一致且integrity_check通过。验证后删除临时库与上传文件。没有修改主3046／8045、既有3049／8047服务和数据，没有模型／短信请求或费用。

## 复现与使用

在本项目backend目录，运行以下自动化可在测试临时库复现：

~~~sh
.venv/bin/python -m pytest -q tests/test_motion_preparation.py
~~~

服务正常启动后自动消费queued任务；新角色生成后登记三类waiting_source任务。旧角色不批量补任务，首次明确提交分类包时登记。操作者确认素材质量并核对本项目数据库与上传目录后，在backend目录运行：

~~~sh
.venv/bin/python -m scripts.queue_character_motion --character-id <伙伴ID> --owner-id <本人ID> --activity rest --pack <分类资源包目录>
~~~

默认仅校验，加--apply才提交本地包。脚本不调用模型，不允许网页用户指定服务器文件路径。GET /api/v1/characters/{id}/motion-preparation返回character_id与activities，每项含activity、state、attempts、error_code；状态包括not_requested、waiting_source、queued、ready、failed。所有接口沿用登录、归属和统一error结构，不返回本地路径、主人ID或后台包输入标识。

新增motion_preparation_tasks表，旧业务表列不改；首次部署更新版前沿用数据库和上传目录共同备份要求。回退旧代码保留新表和任务，旧静态角色与原动作读取继续可用；本轮没有迁移运行中的主库。
