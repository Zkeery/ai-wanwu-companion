## 交付内容

- 创作成功页、伙伴资料页共用「调整性格」弹窗；38 个分组预设，支持多选、自填、组合、主次选择、预览、保存、取消和恢复初始性格。
- 后端保存不可变的原始性格快照及当前配置；所有权、输入和版本校验。旧伙伴打开不写库，首次修改才建立快照；反复修改不扣额度、不重绘图片。
- 多窗口修改冲突、保存回包丢失时先核对，保留本地草稿，不自动重复提交。重新进入可读取保存结果。
- 后续聊天读取当前性格，进行中的任务保留开始时的快照；移除旧的整体300字截断，内核接受完整的预设＋自定义组合。自定义限300字不变。

## 用户复验修正：保存后看起来一直挂起

2026-09-22，用户在弹窗底部反馈保存太慢、一直挂起。核对本地日志，伙伴10的性格PATCH已200；数据库revision=1、预设为laidback（佛系躺平）。日志没有耗时字段，不能据此推断这次请求的确切耗时。原UI把成功提示放在滚动区顶部，底部仍是灰色「保存性格」，缺少用户可见的完成状态。

先补前端手册第5节，再修复：按钮区固定在弹窗底部，状态直接显示「保存中…／已保存／待核对」，成功后可点「完成」；再次修改后恢复「保存性格」。反馈、错误及校验提示与按钮同区显示。性格API等待上限改为3秒，超时保留草稿并核对结果，不自动重发PATCH、不宣称保存失败。

验证：编辑器与请求专项13/13、类型、Lint、隔离生产构建通过。新增测试模拟无回包请求，约3016ms转入TimeoutError且只发出一次PATCH。3020实际页面在1440／390px、滚动顶部／底部4种状态下，已保存按钮均可见且无横向溢出；再次编辑恢复可点击，再取消，未保存任何用户伙伴的测试更改。[截图](保存反馈修复-390.png)、[布局证据](保存反馈布局.json)。这次修正是保存反馈与等待保护，不代表生图性能改善。本轮未提交。


## 用户复验修正：聊天回复后发送按钮未恢复

2026-09-22。用户截图已有回复但仍显示正在回复。主库该轮用户消息和助手回复均已保存，时间相隔约5.8秒；日志包含聊天POST和随后历史／场景GET。该证据不能精确还原浏览器卡住多久，也不能证明这次一定发生了流取消挂起。

代码存在两处额外等待：done后仍等待reader.cancel完成；发送函数在解锁前再次读取历史／场景。先补前端手册第6节，再修复为：解析到服务端持久化done后直接显示确认的回复、提议并清空对应输入，结束发送状态；无需额外GET才能继续。流取消不阻塞完成，终止信号可打断挂起读取，done后的无效尾部不影响已确认结果。首次重新读取历史会替换页面内部的临时用户消息键，不写入虚假服务端ID。

验证：流与聊天组件28/28；前端全量237/237（27文件），类型／Lint／隔离生产构建通过。真实浏览器页面使用明确标记的合成角色与SSE夹具，让连接cancel永不结束、如发生后续GET也永不返回，仍连续通过点击、Enter各发送一次；2次POST、2条确认回复、0次完成后GET，第三条输入后发送按钮可用且无“正在回复”。仅浏览器模拟，不写主库、不调用真实模型、不证明实际模型响应速度。[结果](聊天连续发送验证.json)、[手机截图](聊天发送恢复-390.png)。主用户消息与草稿未改，页面刷新后使用新代码。本轮未提交。
