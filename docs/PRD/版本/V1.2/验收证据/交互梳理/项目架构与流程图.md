更新：2026-09-22。实现基线：V1.1 `0f13a8b`。前两图描述已有代码职责与业务链路，不表示已正式上线或所有真实模型能力已验收。第三至第五图为 V1.2 交互、自主生活与语音规划，尚未开发。

## 1. 技术架构：页面、业务、AI 与存储

```mermaid
flowchart TB
  U[用户：手机网页 / 桌面网页] --> FE[Next.js + React + TypeScript\n页面、交互、登录状态 · 3020]
  FE -->|同源 API / SSE / 鉴权图片| API[FastAPI · 8020\n校验身份、权限、输入和错误]
  API --> AUTH[账号模块\n验证码、会话、数据归属]
  API --> CREATE[创作模块\n上传、识别、构思、生图、改名、收藏]
  API --> CHAT[陪伴模块\n聊天、记忆、场景提议]
  API --> LIFE[生活模块\n庭院 / 绿洲 / 营地\n独居 / 自己的伙伴同住]
  API --> SOCIAL[主题与分享模块\n主题、作品墙、好友小队]
  CREATE --> MC[ModelClient\n模型适配、超时、有限重试、结构校验]
  CHAT --> MC
  CHAT -. 开关启用时 .-> AGENT[受约束场景 Agent\n上下文、工具白名单、任务状态、确认点]
  AGENT -->|通过适配器请求决策| AI[外部 AI 服务\n视觉识别 / 文字构思与回复 / 图像生成]
  MC --> AI
  AGENT -->|用户确认后，经规则执行| LIFE
  AUTH --> DB[(SQLite\n账号、伙伴、聊天、记忆、空间\n主题、分享、任务与确认状态)]
  CREATE --> DB
  CHAT --> DB
  LIFE --> DB
  SOCIAL --> DB
  CREATE --> FILES[(本地角色图片文件)]
  API -->|私人所有权 / 公开状态 / 小队成员权限| FILES
```

这些是逻辑模块，不是多个微服务。当前是一套 Next.js 前端、一套 FastAPI 后端；生活内核、Agent 与普通业务共用项目内持久化存储。前端经同源代理访问后端，模型密钥留在服务端。

短信目前为开发模拟实现；正式短信未接通。场景 Agent 与生成额度已有代码和隔离验证，主环境此前保持关闭，不能把虚线能力说成正式启用。普通创作与聊天按现有配置工作，本轮不调用模型验证效果。

## 2. 业务完整流程：从照片到持续陪伴

```mermaid
flowchart TD
  A[进入产品] --> B{已有伙伴？}
  B -->|有| C[我的伙伴：选择一位]
  B -->|没有 / 想创造新伙伴| D[选择自由创作或主题创作]
  D --> E[需要时注册 / 登录\n再回原操作]
  E --> F[上传照片\n校验格式、大小并识别主体]
  F --> G[结合物体特征构思\n独特形象、名字、性格]
  G --> H[文字外观描述 → 生图\n保存角色图与私人伙伴]
  H --> I[首次见面\n可改名、可纠正、可继续]
  I --> C
  F -. 失败 / 断线 .-> R[保留请求标识，查询已保存状态\n说明原因，再决定是否重试]
  H -. 失败 / 断线 .-> R
  C --> J[聊天与记忆]
  C --> K[选择住处\n庭院 / 绿洲 / 营地]
  K --> L[独居或与自己的伙伴同住]
  L --> M[布置、照料、成长、收纳\n保存，可按规则撤销]
  J --> N[场景变更提议]
  N --> O{用户确认？}
  O -->|确认| M
  O -->|拒绝| J
  I --> P{主题作品，要分享吗？}
  P -->|公开预览并确认| Q[主题作品墙\n可撤下]
  P -->|已加入小队，预览并确认| T[好友小队展示\n可撤回 / 退出]
  P -->|暂不分享| C
  M --> C
```

生成形象由照片特征与完整角色构思驱动，不是只靠名字。改名只改名字；同一主题不要求相同照片或相同结果。生成后默认私人保存，公开墙与小队展示是两次不同范围的用户选择，不会自动互相同步。

图中“我的伙伴 → 生活 → 聊天”共享同一个伙伴与当前住处。生活同住是自己的多个伙伴；好友小队是不同用户的主题展示，不是多人共同编辑场景。

## 3. V1.2 推荐界面结构：让上述模块容易找到

```mermaid
flowchart TB
  ROOT[固定全局导航] --> HOME[伙伴\n首页：伙伴与真实近况]
  ROOT --> MAKE[创作\n自由 / 主题 → 生成 → 结果]
  ROOT --> DISCOVER[发现\n主题与好友]
  HOME --> DETAIL[当前伙伴]
  DETAIL --> TALK[聊天\n对话、场景提议]
  DETAIL --> LIVE[生活\n当前住处、布置、照料]
  DETAIL --> PROFILE[资料\n改名、性格、记忆、管理]
  TALK <-->|同一伙伴、同一场景| LIVE
  MAKE -->|私人保存；结果可去聊天或安排住处| DETAIL
  DISCOVER --> WALL[主题 / 公开作品墙]
  DISCOVER --> TEAM[好友小队]
  WALL -->|带主题进入| MAKE
  TEAM -->|带主题与小队来源进入| MAKE
  MAKE -. 预览并确认后返回对应去处 .-> WALL
  MAKE -. 预览并确认后返回对应去处 .-> TEAM
```

首页以伙伴和近况为主已由用户确认。三项全局导航、伙伴内三项局部导航及返回联动为推荐方案，待整体审阅后编写技术手册与实现。现状仍使用原有导航，不把本图当作已交付页面。

## 5. 新增图：伙伴怎样生活（C 批规划）

```mermaid
flowchart TD
  P[保留私人住处] --> H[独居或自己的伙伴同住]
  P --> V[主人允许后去小队相聚]
  H --> O[观察时间、环境、物件与任务]
  V --> O
  O --> PLAN[AI 提出有限生活计划]
  PLAN --> CHECK[规则核对权限、预算与真实状态]
  CHECK --> ACT[休息散步 / 短交流 / 获准照料与合作]
  ACT --> SAVE[执行结果保存为生活记录]
  SAVE --> NEXT[下一次活动 / 用户参与 / 暂停休息]
  ACT -->|有分歧且想独处：候选情节| HOME[安全结束当前步骤，回家]
  HOME --> CALM[休息、恢复平静]
  CALM -->|愿意时| V
```

用户已确认保留私人住处、去小队相聚，以及自主规划／聊天／完成任务；先完整规划与模拟验证，再核定真实试跑预算。具体作息、权限、调用上限与情绪情节为推荐规则，见 [PRD 第10节](../../PRD.md)。原场景数据保留，共同生活不自动迁移旧主题小队。

## 6. 新增图：心情适配与语音会话（D 批规划）

```mermaid
flowchart TD
  C[同一位伙伴、同一段私人会话] --> TEXT[打字并发送]
  C --> MIC[点击录音，说完发送]
  MIC --> ASR[语音转文字]
  TEXT --> UNDERSTAND[理解当前表达]
  ASR --> UNDERSTAND
  MOOD[用户主动选择或表达心情] --> UNDERSTAND
  UNDERSTAND --> GUESS[轻量心情线索：可纠正、跳过、关闭]
  GUESS --> REPLY[按伙伴性格与当前需要回复]
  REPLY --> SAVE[显示文字并保存同一条会话]
  REPLY --> TTS[语音合成]
  TTS --> PLAY[播放、停止、重播]
  TTS -->|失败| SAVE
```

语音首版交互和心情来源已由用户确认。绘画源于此前理解错误，已作废。转写、文本回复和语音合成分别验证与计费，当前未接入或调用；重试播放不重新发起聊天或重复场景动作。详见 [PRD 第11节](../../PRD.md)。
