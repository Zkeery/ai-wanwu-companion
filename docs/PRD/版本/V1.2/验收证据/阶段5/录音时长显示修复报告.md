# 未发送录音时长显示修复报告

日期：2026-09-24。对应 V1.2 PRD 11.5 第723–725行。按[前端第5阶段技术文档](../../技术文档/前端第5阶段技术开发文档.md)及[后端范围说明](../../技术文档/第5阶段技术开发文档.md)，先记录方案，再修改页面。

用户反馈录制约6秒后看到0。隔离浏览器在旧页面用合成音轨录制6.2秒，录音区显示6秒；音频实际时长约6.3秒，点击试听后 `currentTime` 增至约0.93秒、音频处于播放状态。由此只能确认隔离环境中录音未丢失；不能推断用户当时的原音也正常。旧版原生播放器起始显示0，未明确区分“已播放”与“录音总长”。

现在停止时补算实际录制时长，试听区直接写“已播放N秒 / 录音约N秒”，进度条随播放更新，并提供暂停和继续。播放结束显示完成；失败仍在同一区提示。录音总长取本次计时，不依赖浏览器原生音频时长。试听依然只在本地，不触发识别、发送或后台保存。重录、取消和离开继续清理播放器与对象URL；后端接口及数据未变。

前端语音专项20/20、全量363/363通过；类型检查、Lint通过。生产构建在清空开发短信提示并关闭离线预览标志、使用隔离输出目录后通过；默认开发配置直接构建会被既有生产保护规则拒绝，未降低该规则。自动化使用受控6.1秒录制检查停止后显示约6秒、播放进度、暂停/继续、自然完成与取消清理。

浏览器使用合成音轨独立复验。新页面一次录音在点击停止后显示约7秒，音频元数据约7.3秒；播放位置和进度条前进，暂停后保持、继续后恢复。录制等待与浏览器点击开销共同构成此次7秒，不把它冒充用户的6秒原音。[桌面截图](录音时长显示/桌面试听.png)、[390px手机截图](录音时长显示/手机试听.png)已目视检查；手机视口390px、页面滚动宽度375px，无横向溢出。截图中底部聊天记录区尚未载入音频的历史播放器可能显示0:00，它不代表当前未发送录音；当前录音时长以录音区明确的“录音约N秒”为准。

用户复核：打开[本机体验页](http://127.0.0.1:3043/companions/2/voice)，刷新后重新录约6秒，点“停止录音”，应看到“录音已停止 · 约6秒”；再点“试听录音”，应听到声音，看到“已播放…秒 / 录音约6秒”和进度条，能暂停与继续。若没有声音或出现“试听失败”，保留当前录音并反馈浏览器表现。未发送录音只存在当前页面内存，刷新会丢弃旧录音；本次无法恢复用户之前那段原音。
