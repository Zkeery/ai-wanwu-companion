# VS Code 内置浏览器录音试听修复（2026-09-24）

## 结论与范围

用户在 VS Code 内置浏览器录制约 4 秒，重录后点“试听录音”立即失败。已定位为该内置浏览器无法解码自身 `MediaRecorder` 生成的 WebM/MP4 音频，而非页面计时归零。前端在此环境改用 16 kHz 单声道 PCM WAV 录制；普通浏览器保留原路径。未改变后端接口、上传时机、已发送数据、模型设置或费用。**用户后续反馈本次录制试听“基本上能通过”；第 5 阶段其他环节未完成验收。**

## 原因证据

- 在用户当时的 VS Code 内置浏览器失败页，只读检查未发送录音播放器：`MediaError.code=4`、`readyState=0`，解复用错误为 `DEMUXER_ERROR_COULD_NOT_OPEN`。
- 在同一内置浏览器使用独立合成音轨生成 WebM/Opus 14,786 字节与 MP4 15,246 字节，均非空，但播放器均报媒体错误 4；`decodeAudioData` 也不能解析该 WebM。浏览器报告格式可录制、可播放，不代表实际文件能被解码。
- 同一内置浏览器可以将本地构造的 16 kHz 单声道 PCM WAV 加载至 `canplay`，时长 1 秒。后端原有 `validate_audio` 接受 WAV，8 MB 上限大于本次 60 秒录音约 1.92 MB。

## 实现与验证

实现依据先写入[前端第 5 阶段技术文档](../../技术文档/前端第5阶段技术开发文档.md)和[第 5 阶段技术文档](../../技术文档/第5阶段技术开发文档.md)，再修改前端。VS Code 内置浏览器从麦克风流收集 PCM、结束后生成 WAV；录音轨道只接零音量输出。其他浏览器等最终 `dataavailable` / `stop` 后再释放轨道。空文件不能进入可试听状态；录音整理期间锁住下一次操作；试听错误按无数据、格式不支持、播放阻止分别提示。历史音频播放器只在实际加载成功后出现，避免用户误点其“停止播放”控制。

前端 38 个测试文件、367/367 项通过；TypeScript、ESLint、隔离生产构建通过。自动化涵盖 WAV 头、采样率、声道、体积、MediaRecorder 异步收尾及空录音。隔离 Chromium 伪装 VS Code 标识并使用合成音轨，完成“开始录音→停止录音→试听”，WAV 时长约 3.24 秒，播放时 `paused=false`、`MediaError` 为空且进度前进；390px 页面无横向溢出，历史播放器初始隐藏。这项合成音轨验证与下述用户实际操作反馈分开记录。
