# 未发送录音试听反馈修复报告

日期：2026-09-24。对应 V1.2 PRD 11.5 第723–725行。收到“试听录音”按钮无反应的页面反馈后，先复现并补[前端技术开发文档](../../技术文档/前端第5阶段技术开发文档.md)与[后端范围说明](../../技术文档/第5阶段技术开发文档.md)，再修改页面与测试。

## 原因与修复

旧页面的“试听录音”按钮把本地录音交给位于下方“聊天与音频记录”区的共用播放器。隔离浏览器用合成音轨录制后点击该按钮，播放器进入播放状态，进度从0增加到约0.84秒，但录音按钮旁没有状态或控件；若播放失败，错误也只出现在页面顶部。这能解释当前截图中“点了却看不到反应”的体验，不能据此断定用户设备当时已经出声。

现在未发送录音在按钮下方有独立播放器和就近状态：点击后显示“正在播放录音”，自然结束显示“录音播放完毕”，失败提示重录或改打字。重录、取消、发送后清空、离开时停止试听并释放本地对象URL。已发送音频继续使用聊天记录区播放器。试听不会上传、识别或发送录音，不新增后端接口、模型调用或费用。

## 验证

- 前端语音专项 20/20、全量 363/363 通过；类型检查、Lint（无警告）和生产构建通过。测试覆盖播放开始/结束、失败就近提示、重录/取消后释放对象URL及零发送。
- 隔离浏览器使用合成音轨而非真人麦克风，复验录制→停止→试听：播放器与按钮相邻，播放进度前进，结束后状态变为“录音播放完毕”。[桌面局部截图](未发录音试听反馈-1440.png)、[390px 手机局部截图](未发录音试听反馈-390.png)已目视复核；390px 页面滚动宽度为390px。
- 本次只有前端交互变更，后端契约与数据未变；后端沿用上一增量1078/1078全量结果，不把此结果冒充真人语音验收。

用户复核：在这台电脑打开[隔离体验页](http://127.0.0.1:3043/)，选择自己的伙伴→“说话”，刷新页面后重新录一小段，点“试听录音”。按钮下方应立即看到播放器和状态；能听到并看到进度，再自然结束。若显示“试听失败”，保留录音文字并可重新录制。刷新可能清除原先未发送的录音；它不会被后台上传。
