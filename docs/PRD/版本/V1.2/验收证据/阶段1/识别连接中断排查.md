# 识别连接中断排查

日期：2026-09-22。来源：用户在正式创作页上传图片后出现“识别失败，请重试”的截图。先补充前后端第1阶段技术手册，再进行以下修复。

## 已确认的原因

最新识别记录的图片预处理成功，耗时213ms；识别调用15571ms后失败，安全类别为`connection_interrupted`，接口返回502，未进入伙伴生图。该类别来自HTTP客户端的请求异常，不等同图片过大、格式不支持或内容不合适；旧日志没有更细的传输类型，不能据此断言具体是模型网关、代理还是其他网络环节断开。

还发现两处产品错误处理问题：后端有失败分类，但识别接口丢掉分类、统一返回模糊提示；前端把所有502都当作确定失败，包括代理返回且结果未知的502，可能使用户跳过原请求核对。

## 修复

- 识别接口按安全类别提示连接中断、无法连接、超时、授权异常、繁忙或格式异常；保留502和`recognize_failed`，新增安全`reason`字段，不暴露供应商正文、URL、凭证或异常堆栈。
- failed回执先保存，再返回错误；同一请求键再次提交不重复调用模型。当前页原文件继续保留，主动点击重试才使用新请求键；不增加自动重试、延长超时或切换模型。
- 前端只将已知`recognize_failed`的502视为确定失败；其他502进入结果核对，保留原请求。
- 日志增加白名单传输类别，下一次失败可以区分协议中断、读取、写入、代理等；仍不保存原始异常内容。

## 验证

后端照片接口、生成错误及生成优化相关61/61通过；前端创作流程34/34通过；类型、Lint、隔离生产构建通过。新增验证覆盖失败回执持久化、同键不重调、失败不创建伙伴、供应商401不误注销用户、日志脱敏、文件保留与手动新键重试、未知502核对。全部使用隔离数据与网络替身，没有收费模型调用。

本地8020更新前确认照片／伙伴生成、Agent聊天及额度预留均无进行中任务，保存SQLite备份后正常重启。无数据迁移、无模型配置变化。旧页面已经显示的模糊错误属于旧响应，只有新请求才使用新提示。
