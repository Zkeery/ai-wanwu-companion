# R1.3 动作资源与离线播放

2026-09-26。上一批已提交 `47a7e25`；本轮先写[后端手册](../../../技术文档/第1阶段技术开发文档.md)和[前端手册](../../../技术文档/前端第1阶段技术开发文档.md)，再开发独立播放器。对应PRD角色本体动作、固定背景、失败保留静态及减少动态偏好条款。**本轮仅为手绘素材工程验证，真实照片动作未完成，阶段1与V1.2未通过整体验收。**

## 用户体验

打开 http://127.0.0.1:3045/motion-preview 。第一张杯子卡片加载好后，将鼠标移入形象，身体和手脚开始动；移开恢复静态。手机点“跳个舞”，再点“停止动作”。第二张明确没有动作素材；第三张展示加载失败，点“重新加载动作”只重读同一份素材，不生成图片。

页面保持“手绘测试素材”提示，没有使用你的伙伴照片。真实伙伴素材的主体分离、背景补全、动作制作及私有绑定留到后续开发；不把整图平移当成角色动作。

## 实现

- 后端纯离线校验manifest版本、源图标识、PNG真实格式、尺寸、帧数／FPS、文件摘要、单帧透明度和固定背景；拒绝符号链接、过大文件、不合法路径、错尺寸和空白帧。不新增业务API或数据库迁移。
- 前端静态图绘制后开始10秒资源准备；SSR已缓存的图片也能启动准备。超时／失败保留静态，手动重试；旧请求与卸载后的回包不会改变新状态。
- Canvas从透明横排帧图取角色帧，背景每帧相同。鼠标移开、切到后台、减少动态偏好或卸载时停止；手机按钮可启停。Canvas不拦截指针。
- 预览默认404，仅 `MOTION_PREVIEW_ENABLED=true` 开启。3020／3043等已有服务未重启、用户数据未改动。3044被已有进程占用，独立预览改用3045，不修改默认项目端口。

首次浏览器复验暴露SSR缓存图片先于React接管加载，导致准备一直等待；已先补修订手册再修复，并加入回归测试。初次悬停结果见[原始记录](browser-checks.json)：角色帧没有变化。后续记录发现工具操作之间产生visibilitychange隐藏页面，触发正常后台停止，不能据此判断悬停失效。最终以CDP `Emulation.setFocusEmulationEnabled` 保持前台可见，再用实际浏览器指针复验；角色像素变化与移开停止均通过。测试后恢复焦点和减少动态模拟。未移除后台停止保护，未注入假鼠标事件。

## 重现

在本项目目录运行：

```sh
cd backend
.venv/bin/python -m pytest tests/test_motion_assets.py -q
cd ../frontend
npm run test -- tests/motion-player.test.tsx
npm run typecheck
npm run lint
NEXT_DIST_DIR=.next-motion-r13 NEXT_PUBLIC_DEV_SMS_CODE= NEXT_PUBLIC_OFFLINE_PREVIEW=false NEXT_PUBLIC_LIFE_RUNTIME_PREVIEW=false npm run build
NEXT_DIST_DIR=.next-motion-r13 NEXT_PUBLIC_DEV_SMS_CODE= NEXT_PUBLIC_OFFLINE_PREVIEW=false NEXT_PUBLIC_LIFE_RUNTIME_PREVIEW=false MOTION_PREVIEW_ENABLED=true npm exec -- next start --hostname 127.0.0.1 --port 3045
```

先检查3045未被其他进程使用；当前预览已启动，不重复启动。测试不读Key、不调用模型。手绘素材已经在frontend/public/motion-preview-assets提交候选目录；制作脚本默认dry-run，只有显式 `--write` 生成同一示意素材。实际PNG契约摘要见manifest.json，跨进程可再次校验。无需重绘用户图片。
