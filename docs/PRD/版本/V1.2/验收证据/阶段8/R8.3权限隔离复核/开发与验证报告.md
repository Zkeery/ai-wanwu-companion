# R8.3 私人资源与退出后授权隔离复核

2026-09-24。先补[后端第8阶段手册](../../../技术文档/第8阶段技术开发文档.md)和[前端第8阶段手册](../../../技术文档/前端第8阶段技术开发文档.md)，再按 V1.2 PRD 6.3、10.8、11.6 复测双账号 HTTP 权限。测试只使用后端临时 SQLite、合成 PNG/WAV 和离线回复，没有调用模型、短信或云资源，也没有修改真实用户库、主服务及前端页面。

## 接口结果

上述结果来自新增 `backend/tests/test_stage8_privacy_matrix.py` 的 FastAPI HTTP 请求；它还用重新构造的 `GatheringStore` 核对退出者仍无法读取、主人仍可读取。所有本轮被拒绝的资源响应都不含原图片或音频字节，并带 `Cache-Control: private, no-store`。测试未用前端按钮隐藏来证明服务端权限。

## 失败、修复与复验

首轮测试失败：语音资源匿名错误响应虽然返回 401，但缺少 `Cache-Control`。原因是原 `no_cache` 路由依赖在认证失败时尚未完成，缓存头未写入。按手册修复 `backend/app/main.py` 的统一 HTTP 响应边界，让 `/api/v1/` 与私人 `/uploads/` 的正常及错误响应均含 `no-store` 和 `Vary: Authorization`。

第一次全量回归有 12 项失败：直接覆盖缓存头抹掉了流式生成所需 `no-transform`，也改变了小队／作品墙已有的精确 `no-store` 响应。已改为保留原有指令，仅在缺少时补 `no-store`；相关 62/62 先通过，随后后端全量 **1116/1116** 通过。前端代码未改，本轮不重复 R8.2 的前端类型、Lint、构建与浏览器检查。两条依赖弃用警告未影响本轮结果。

复查命令：在 `backend/` 运行 `.venv/bin/python -m pytest -q tests/test_stage8_privacy_matrix.py`，应为 1 passed；运行 `.venv/bin/python -m pytest -q`，本轮为 1116 passed。测试启动时强制使用临时库和空模型 Key，不需要真实登录、短信或用户图片。
