## 2. 数据与一致性

- 新增 `character_personalities` 表，以 `character_id` 为主键和级联外键；保存原始性格、预设 ID 数组、自定义文字、优先项、模式及递增 revision。
- 旧伙伴未编辑时 GET 返回其现有 `Character.persona` 作为原始性格，revision=0，不写库。第一次保存同事务保存原始快照与当前有效性格；后续保存永不覆盖原始快照。
- `Character.persona` 继续保存当前有效性格，兼容已有列表、资料和聊天。恢复原始性格仍递增版本，不删除版本记录。角色删除时级联清理。
- 先完成数据库与生成图片的共同备份、隔离恢复校验，再让主服务创建新表；不改旧表字段、不改生成资产。每次修改锁定角色并校验 expected_revision，过期返回 409，不能静默覆盖另一个窗口。

## 3. 性格目录与校验

保留 PRD 推荐项、社交、情绪、做事、立场、反差与补充标签；预设按稳定 ID 存储。重复 ID 去重，已列出的同义项使用同一 ID 并向用户提示。不强制 3–5 项，最多为目录总数。自定义最多 300 个 Unicode 字符，空白不能擦掉性格，超长拒绝，不截断或改写用户输入。

明确冲突使用小型规则表，返回具体组合提示，不用额外 AI 调用猜测。反差设定可以共存。预设与自定义同时存在时，用户必须明确选择「预设为主」或「自定义为主」，预览和后续上下文均说明主次；不声称确定性规则能理解全部自然语言矛盾。

有效性格包含标签与主次说明，聊天内核接收上限为2000字；自定义输入上限仍为300字。不得沿用旧的300字整体截断丢失后半段描述。

自定义仅是角色描述数据，不是系统权限；性格不能授权工具、删除、费用动作，不能压迫或羞辱用户。模型上下文以 JSON 数据承载名字和有效性格，保留确定性权限与场景确认规则。强烈性格作为表达风格，不作心理诊断。

## 4. API 契约

所有接口要求登录；他人或不存在的伙伴返回 404，未 ready 返回 409，响应 `Cache-Control: private, no-store`。

| 方法与路径（前缀 /api/v1） | 请求 | 响应 |
| --- | --- | --- |
| GET /personality-options | 无 | options、conflicts、max_custom_length、catalog_version |
| GET /characters/{id}/personality | 无 | character_id、original_persona、effective_persona、mode、tags、custom_text、priority、revision |
| PATCH /characters/{id}/personality | expected_revision、mode(original/custom)、tags、custom_text、priority(presets/custom/null) | 保存后的完整性格状态 |

统一错误 `{"error":{"code":"...","message":"..."}}`；无权限 401，参数或冲突组合 422，版本冲突 409 `personality_conflict`，存储暂不可用 503。PATCH 不调用模型，不自动重试。网络结果不明时先 GET 核对；只有确认并经用户再次操作才提交新版本。

## 5. 生效边界

保存成功后的新聊天读取有效性格；已经开始的回复使用开始时快照，不重启。保留名字、照片来源、生成构思、图片、开场白、记忆、历史、住处和生成额度。恢复原始性格不重新生成形象。不提前实现语音、共同生活规划或比赛模块。

## 6. 验证与门槛

覆盖本人/匿名/他人、未 ready、旧数据懒初始化、预设/自填/组合/恢复、重复/非法项/长度/空值/冲突、版本并发、回执核对、删除级联、新进程读取、原图与额度及历史不变。检查聊天快照读取新性格和进行中任务保持旧快照；模拟不代表真实模型表现。

本地性格读取和保存目标 ≤500ms（请求发出到收到完整响应），记录样本而不冒充生产 SLA。模型个性效果仍待有预算的真实验收。证据及阶段闸门写入 `../验收证据/阶段2/`。

## 7. R2.2 来源联动的后端契约（2026-09-22，开发前约定）

本轮复用现有接口，不新增表、字段或模型调用。来源与列表位置是前端导航信息，不是服务端授权依据。

| 操作 | 既有接口与约束 |
| --- | --- |
| 回到小队 | GET /teams/{team_id}，验证成员身份；退出／解散返回404 |
| 小队预选伙伴 | GET /characters，只读取当前账号；前端筛选同主题且 ready、有图 |
| 确认小队提交 | PUT /teams/{team_id}/submissions/{character_id}，后端再次验证成员、所有者、状态、主题、图片；同一伙伴重复提交不重复记录 |

错误沿用统一 error.code/message；网络结果不明时沿用现有核对流程，不能因返回入口而重做生成、扣额或分享。无需数据库迁移或主服务重启。回归现有小队与作品墙权限、重复提交、退出／解散、公开撤回测试；证据与前端同归阶段2报告。

## 8. R2.3 邀请与生成闭环联调（2026-09-22，开发前约定）
