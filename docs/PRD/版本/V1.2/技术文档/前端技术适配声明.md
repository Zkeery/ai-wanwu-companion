# 前端技术适配声明

- 日期：2026-09-22；依据：[PRD](../PRD.md)、[开发计划](开发计划.md)。
- 状态：代表页与交互结构待用户体验反馈；正式业务前端尚未替换。

## 1. 复用现有工程

继续使用项目已安装的Next.js App Router、React、TypeScript、现有CSS与lucide-react，不升级依赖。现有路由、登录恢复、聊天草稿、请求核对与私人图片鉴权保持兼容。后续写框架代码前读取本地`node_modules/next/dist/docs/`对应指南。

## 2. 信息架构

全局固定“伙伴／创作／发现”；伙伴内固定“聊天／生活／资料”。全局表达用户在哪里，局部表达正在和哪位伙伴做什么；进入场景时不把全局导航替换成聊天和场景按钮。

未登录首页仅一个注册／登录按钮；已登录首屏显示伙伴和有依据的近况。发现页将主题活动、公开作品与好友作品小队分开，未来共同生活不能冒充当前作品小队功能。

## 3. 视觉与交互

采用Tiffany蓝绿为主视觉，奶油白卡片、深紫文字、珊瑚粉与黄色点缀；色彩吸睛，主操作层级明确。保留用户偏好的温馨、可爱和梦幻感，不把原型做成后台管理台。

桌面侧边固定全局入口；手机底部固定同样三个入口。中文使用系统字体，正文至少16px，触控目标至少44px；390／768／1280／1440宽度不出现横向溢出，底部留安全区域。

卡片位置在悬停时保持稳定；示意角色只让身体和手脚动作，背景不动，减少动态偏好下不自动跳舞。原型SVG不代表生产照片已完成主体分离或动画生成。

## 4. 状态与数据来源

URL表达全局页面、伙伴id、局部分区；聊天草稿仍按当前账号与伙伴隔离。业务数据来自后端；加载、空、失败、成功各自展示，不用错误状态替代空数据。切换分区不主动发送聊天、生成、搬家或发布。

原型使用文件内固定示例，不请求真实API、不读取登录令牌、不上传选择的照片；顶端常驻“交互原型”标识。示例会话和近况明确说明，用户录入的演示草稿只驻留本页内存，刷新不承诺保存。

## 5. 本阶段交付

先按[前端第1阶段技术开发文档](前端第1阶段技术开发文档.md)开发独立交互原型并检查桌面、手机、返回、草稿保留与空／错状态。随后接入正式组件与真实查询，按同一手册验证；原型通过不能宣布第1阶段业务完成。

语音、性格多选编辑、真实自主生活、比赛与模型切换各按后续阶段实施。原型只演示本阶段模块组织，不提前创建这些业务功能。
