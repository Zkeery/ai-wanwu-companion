# 云部署方案与费用清单

核对日期：2026-10-01。当前为R8.14方案准备，未部署；推荐平台、预算和购买尚未获确认。上一批工程与证据本地提交为`fc7a970`，未推送。

## 推荐与适用范围

推荐首批5–10人内测使用火山引擎北京区单台ECS，4核8GiB、本机挂载的持久块磁盘，保留Next.js、Python API和SQLite。另用同地域私有TOS保存完整备份。继续采用国内数据部署、个人认证与手机号验证码登录的既有决定。当前短信资质缺失，先准备部署文件，暂不购买或发布。

这是一项待确认的托管方式调整。共享部署手册默认veFaaS预留实例＋SQLite过渡，但项目现在已有应用内持续后台worker；[官方Native Web应用规范](https://docs.volcengine.com/docs/vefaas/Native_runtime_Development_methods_Web_applications?lang=zh)说明不能保证请求结束后后台进程／线程存活。常驻容量配置也不能替代本项目实际长时间运行验证。

veFaaS可以[挂载NAS](https://docs.volcengine.com/docs/vefaas/Mount_FileNAS?lang=zh)，还需VPC和独立存储资源；不能据此认定当前SQLite部署安全。[SQLite官方说明](https://www.sqlite.org/wal.html)限定WAL用于同一主机，不能运行于网络文件系统。结合现有SQLite配置和worker实现，本轮推荐本机块磁盘，避免引入新的数据库、网络文件系统或调度改造。未来扩容／RDS切换须另做迁移设计和验收；项目源码含SQLite专用限制，不能声称只换连接串即可。

## 数据恢复与运行边界

当前体验库／uploads／ledger只读大小分别为3,112,960／2,307,106／15,555,519字节，合计约20MiB；不是容量或生产备份压缩比保证。业务盘80GiB包含操作系统与发布空间，20GiB TOS是月均估算，应按实际快照和留存调整。

云备份候选目标为每5分钟捕获一次，保留最近一小时的5分钟版本、24份小时版本及7份日版本，成功上传后才更新完成标记。必须用现有SQLite一致捕获及文件清单流程，不能用正在写入的`.db`简单复制；先在新目录恢复，再核对表、文件、额度和后台任务。目标RPO≤5分钟仅在定时任务与上传持续成功时成立，尚未实测；备份失败须可见，恢复由明确流程执行，空库或挂载丢失不得自动覆盖原数据。

首版仍只能单实例，不能自动扩容。云盘与主机重建的保留策略以及TOS异机恢复必须实际验证；同一块盘上的备份不能算灾备。个人认证过渡路线并未解除这三项已有业务限制：单实例、灾难恢复可能损失最近备份后的数据、不能随用户量扩容。

## 实施顺序与剩余验收

1. 先完成x86目标打包／原生库、systemd服务、同源HTTPS入口和备份上传脚本的可审查文件；仅本地离线工作，不创建云资源。当前模板不满足production启动条件。
2. 真实短信资质准备好时，再核对域名／备案资源与业务材料。个人云账号认证不等于短信签名和模板审核；两者分别保留待验，不催用户重复提供暂无的材料。
3. 给出真实三个月订单与用量预算，确认ECS候选、备案条件及费用后才采购；用户本次继续授权不等于这项采购批准。
4. 目标云机重新安装／构建；配置挂载、原生库、生产Secret及真正SMS配置后检查启动保护。正式模型／短信批次须另给次数和金额，不使用合成值绕过生产保护。
5. 在真正HTTPS环境复验双账号隔离、错码／过期码、手机麦克风、核心流程、SSE收尾、静态资源、进程重启、主机恢复、跨设备及备份下载恢复；保持费用与权限持久化。长期worker稳定性及真实8秒性能门槛仍分别待验。

开发与配置估计2–3个开发工作日，前提是目标系统、平台权限、Secret和域名可用；x86兼容异常可能增加时间。备案、短信审核及用户真实设备验收另计，不承诺发布日期。准备文件可继续推进；本轮不购买、不公开体验服务，也不宣布第8阶段／V1.2完成。
