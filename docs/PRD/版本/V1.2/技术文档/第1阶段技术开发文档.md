## R1.5 动作自然度修订（2026-09-27，反馈后开发前）

用户认为首版动作不自然、幅度小，首版美术验收未通过。先修当前样例，不进入下一阶段。原图、首版rig与证据保留，新结果单独归档到R1.5证据目录的自然度修订。

首个加大幅度候选检查未通过：身体与脚部出现脱节。修复前补充约定：ground层上端根据躯干支点位移做有限仿射拉伸／剪切，底部20%接地区域保留原像素；抬脚时再执行局部起落。取样仍来自原脚，不添新结构。支撑像素测试针对脚掌底部，允许脚的上端跟随身体变形。

首版同一正弦驱动身体与手臂，且全身变换连带支撑脚，幅度保守。新增兼容旧输入的rig v2：每层明确space=body或ground。body层跟随共同躯干支点，手臂通过相位错开；ground层不跟随身体整体旋转／平移，只有抬脚半周期参与局部动作，使用max(0,sin)^2使起落速度连续，落地半周期保持原位。v2身体上下起伏用bob*sin(phase)^2，不改变v1语义。仍只改变已有部位，不增画脸或肢体，不移动背景。

重心方向复核：身体向左时由左脚支撑、右脚抬起，反向亦然，双脚相位据此安排。仅本轮新建且尚未交付的隔离“轻快摆动”测试伙伴允许在验证其原图与旧素材摘要后同事务替换实验绑定，旧实验素材进入持久化清理队列；首版苹果及其他伙伴不变，公开导入仍拒绝覆盖。

制作入口默认dry-run，--write才创建新输出目录；拒绝覆盖已有目录及链接，先写临时目录，完成R1.3校验再原子发布。输出固定background.png、sprite.png、manifest.json，source_sha256必须是原始输入文件摘要。另交付部位标注图与若干帧对照、耗时与人工步骤记录，全部标明已有生成图／人工标注／本地动作。流程中不绑定真实用户伙伴。

测试覆盖错误源图／rig版本／摘要／轮廓／数值／输出预算、现有目录保护、失败清理、确定性输出、背景恒定与部位独立变化、生成结果通过R1.3验证，并可经R1.4导入。浏览器仅向本轮3046／8045隔离账号增加“苹果样图·动作试作”，保留此前两个示意伙伴，不替换用户数据。先验证登录、原图、私有素材、播放／停止与重开，再交用户评价自然程度。制作性能单独记录，不宣称正式新图8秒或动画10秒已达标。

## R1.3 动作资源契约与离线播放（2026-09-26，开发前约定）

用户同意先commit再推进伙伴本体动作，画风适配已提交`47a7e25`。现有正式照片无分层或动作素材；本增量只交付可验证的资源校验器与独立播放页，不用整张照片晃动或手绘示意冒充真实伙伴完成。下一增量R1.4再设计所有权、私人素材交付和正式伙伴绑定，本轮不向真实业务数据库写动作状态。

### 资源方案

第一版采用预先制作的透明PNG横向帧图＋固定PNG背景，前端Canvas按帧绘制角色，每帧背景位置固定。它是2D素材播放，不声称拥有3D模型／骨骼或能自动让任意照片动起来。素材生产可独立选择本地工具或模型，本轮不调用生图／视频／分割服务，也不增加依赖。确定性手绘杯子动作仅验证契约，全页常驻“动作示意”标识，不作为R7.14真实形象或旧伙伴动画。

manifest字段：`version=companion-motion-sprite-v1`、`source_sha256`、`frame_width`／`frame_height`（64–512整数）、`frame_count`（2–24整数）、`fps`（4–24整数）、`sprite_file`／`background_file`（同目录PNG安全basename）、`sprite_sha256`／`background_sha256`。原图哈希由调用者单独传入，不能相信manifest自我声明。JSON未知字段、布尔当整数、错误版本、源图不匹配、文件路径逃逸／符号链接、非PNG、摘要不符、尺寸与横向帧数不一致、帧图没有透明区、背景不完全不透明、单文件>10MiB一律拒绝。总解码像素上限7M，透明度与运动是否保留身份仍需人工检查，代码不能替代质量验收。

`backend/app/services/motion_assets.py`提供纯本地验证，无Key、网络、数据库、副作用；成功返回规范化manifest，失败抛固定安全错误。公开目录仅存手绘示意，真实私人图不进入public。示意manifest和PNG持久保存，跨进程复验哈希绑定与可恢复性；不保存浏览器计时为业务任务状态。

### 闸门与后续

测试真实PNG读取与类型／大小／哈希／路径／透明／尺寸边界、源物绑定、跨进程复验。执行前端加载、就绪、缺素材、失败、10秒边界、停止／重试、卸载、快速切资源、减少动态偏好与隐藏标签页验证。资源有效只代表工程兼容，首次最终图显示后≤10秒动画准备仍只验证离线条件；正式照片源图8秒和真实素材10秒待验。

## 3. 接口契约

`GET /api/v1/characters/overview`，沿用Bearer鉴权，无必填参数；静态路由注册在`/{character_id}`之前，避免路径误匹配。

响应200为数组，每条包含：

| 字段 | 类型与含义 |
| --- | --- |
| character | 现有CharacterOut，不改变旧字段语义，只含本账号ready伙伴 |
| residence | null，或`{space_id: string, scene_type: home/desert/forest, mode: private/shared}`；仅已保存且属于本账号的有效当前位置 |
| last_interaction_at | 最近一条已持久化私人会话消息时间，ISO时间或null；不是在线或心情状态 |

空账号返回`[]`。没有住处为null，前端显示“选择住处”；没有消息为null，显示“还没有聊天记录”，不以opening_line冒充近况。失效或不属于本账号的space引用不得泄漏空间资料，返回null并记脱敏诊断。

错误沿用`{"error":{"code":"...","message":"..."}}`：未登录／失效401；内部失败使用安全的5xx，不泄漏堆栈。查询失败不返回假空列表，用户手动重试，不触发生成或变更。

## 4. 数据与实现

复用`Character.owner_id/status/current_space_id`、既有聊天记录及场景存储。按owner限定字符集合，批量关联住处、按character聚合最近消息，避免N+1。目标最多3组批量读取，具体SQL与存储连接边界在实现时核对，不先做每伙伴scene调用。

禁止调用会初始化场景的GET scene或写入式bridge方法。读取不得创建住处、更新位置、消耗额度或改变生成请求。复用现有会话管理，空／断裂引用分别覆盖测试。

不新增持久化层；创建或迁移字段如确实必要，先修订本手册并完成V1.1 R6.3备份恢复，不悄悄扩范围。多账号隔离在后端完成，前端隐藏不足以通过。

## 5. 性能与失败边界

本地验收数据集：100个伙伴、每位20条消息；记录环境、样本数和逐次耗时，热请求目标≤1秒，查询数量不随伙伴数量线性增长。该值是本阶段查询目标，不代表生产网络无延迟，也不替代生成≤8秒门槛。

前端沿用既有15秒请求保护，错误提示与重试保留；不把请求保护时限当成可接受的交互延迟。静态导航响应目标100ms内出现反馈；真实耗时在联调证据中报告。
