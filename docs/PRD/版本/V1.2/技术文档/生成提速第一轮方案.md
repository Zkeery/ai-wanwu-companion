# 生成提速第一轮方案

2026-10-02 用户授权按建议优化生成时间。本轮先执行无新增模型费用的工程优化，保持最终图片显示≤8000ms的既有标准，不更换模型、不降低分辨率或画质，不挪用已授权验收账本。

## 依据与目标

对应 PRD 第9节生成性能及超时恢复。最新网页上传至显示16181.4ms，其中识别2324.7ms、生成至ready12507.2ms、ready至绘制1335.2ms；Wan HTTP11802.4ms。现有连接复用、识别缩图与SSE完成即返回继续保留。工程开销优化不能据此宣称8秒达标。

## 后端实施范围（第3阶段增量）

- 图片下载使用已有有界HTTP连接池，继承既有开关及超时；授权只随模型POST发送，下载不携带API密钥。授权不写入客户端默认请求头，重定向行为保持。
- 生图HTTP、图片下载、文件落盘分别记录耗时和成功／失败，沿用外层生成任务标识；未处于生成任务时使用独立随机标识。日志只含阶段、标识、毫秒和结果，不记URL、提示词、图像、密钥和原始异常。
- 数据库结构、图片原始字节、状态机、费用预留、自动重试策略不变。源代码验证在隔离环境执行，不重启正在运行的真实24小时验收服务。

## 前端实施范围（第3阶段增量）

私有图片只在地址、账号或手动重试发生变化时重新下载。父组件的失败回调变化不取消当前请求、不撤销已显示图片；真正失败时调用最新回调。继续保留账号切换立即隐藏、迟到响应隔离、手动重试和Blob释放。

## 验证与交付

先用回归复现回调变化重复下载，再修复。后端用本机真实HTTP服务器核对多次生成的TCP连接复用、POST授权隔离、重定向、原始图片字节以及成功／失败分段计时；模型端为本地替身，禁止称为真实模型测速。前端跑相关回归、类型检查、Lint和隔离生产构建，按1500／390宽度检查已有生成流程。结果归档到`../验收证据/阶段3/生成提速第一轮/`，更新README和项目状态。

真实模型优化后全链路耗时仍待独立授权测速，旧16.2秒原样保留。下一轮若筛选更快模型，先核实能力、画质条件、逐次样本与具体次数／费用，再执行收费实验。本轮不承诺节省具体秒数。

## 已排除的方案

对三张既有1024图做内存无损WebP试验，体积减少约22%—28%，编码约485—593ms。因首次编码开销可能抵消本地传输收益，不加入首次出图路径；原文件未修改。客户端预先降低照片质量、模型分辨率和取消照片特征也未采用。

## 执行结果

89／89后端、71／71前端及类型／Lint／独立构建、1500／390浏览器与隔离服务重启恢复通过。真实模型0次，8秒仍未通过；本轮源码优化尚未通过新的真实入口后端重启和模型测速验收。详见[结果与证据](../验收证据/阶段3/生成提速第一轮/优化与验证报告.md)。
