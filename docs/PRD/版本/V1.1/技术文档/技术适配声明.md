## 1. 产品与技术方案

产品链路：自由拍摄或选择主题 → 上传物品/植物照片 → 自动识别并生成独特形象、名字和性格（结果可纠正） → 用户改名与收藏 → 自选庭院/沙漠/森林及独居/同住 → 聊天、照料、自由布置 → 主动向作品墙或好友小队分享。全部属于同一个首版，分阶段仅用于开发和验证。

沿用 Next.js/React/TypeScript、FastAPI/Python 3.12、SQLAlchemy/SQLite。图片与聊天生成流程继续复用，场景规则由确定性代码执行；R4 已将受约束工具循环接到场景接口，正式开关仍关闭。不把蓝图工具放进产品运行链路。无需新增模型、消息队列或常驻成长任务。

R1 场景内核、R2 账号与多场景接口、R3 界面和旧花园兼容、R4 工程及体验修复均已有交付记录。当前支持三种场景与独居／同住；R3/R4 真实质量与用户视觉满意度待验。最新修复提交 a9dfce2，不能将继续工程开发视为旧闸门通过。

用户已授权按本手册继续开发。旧 S1 的真实模型待验仍保留；本轮纯工程模块可以独立验证，不宣称旧闸门通过。付费调用继续暂停。

## 2. 分阶段执行顺序

| 阶段 | 本阶段交付 | 依赖与通过条件 |
| --- | --- | --- |
| R1 场景与养成内核 | 三场景目录、私人/共居空间类型、稳定物件、成长/照料、移动/收纳/摆出、单步撤销、持久化、幂等与冲突检测 | 隔离自动检查、跨进程恢复、旧数据不变；不要求模型或前端 |
| R2 账号与多场景接入 | 手机号账号与后端会话、伙伴归属、用户选择独居/同住及成员、当前位置、API、旧花园兼容迁移 | 后端真实隔离、短信适配验收、迁移/删除/回退通过；短信费用或平台信息缺口到该阶段解决 |
| R3 温馨移动端体验 | 首页单一注册/登录入口及轻弹窗、生成与收藏、三场景代表页、居住选择、照料、拖拽和收纳 | 淡紫/淡粉/奶白；手机与桌面、无障碍、错误恢复；真实接口联调 |
| R4 伙伴生成与场景 Agent | 差异化生成与主动再创作、伙伴上下文、场景白名单工具、确认/拒绝/过期、限步和恢复 | 原链路回归；真实样例与费用授权后验收；不凭 mock 判定独特性 |
| R5 同题创作与社交 | 主题、作品墙、主动发布与撤回、好友小队与邀请 | 默认私人、权限隔离、成员退出/删除一致；不能延期为下一产品版本 |
| R6 完整首版验收与上线准备 | 配额/失败回退、成本限制、性能与质量、数据生命周期、备份/恢复、部署与内测 | 预算与定价等待定项关闭，整条链路证据齐备后才上线 |

每个阶段先细化契约再开发，检查通过并交证据后推进。R5.1 个人主题、R5.2 作品墙、R5.3 好友小队工程已实现并完成离线验证；当前推进 R6.1 只读上线预检，真实质量待验保留。涉及外部平台、费用或真实模型的操作单独遵循已有授权范围。
