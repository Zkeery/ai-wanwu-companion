# 网页体验整改技术方案

2026-09-19。用户在3020真实开发版反馈“响应慢、图片生成慢、页面不够炫酷、小花园种类少”。先写本文再实施，验收后迭代唯一PRD，不用已有单次性能通过代替用户体验认可。

## 已确认方向

- 视觉：明亮潮玩感，大胆配色、大角色、弹性动效。重做收藏代表页，并统一创建、聊天和花园的视觉语言；兼顾手机与减少动态效果偏好。
- 生成：图片、人设、开场白全部完成后才进入，不采用先聊天后补图片。保留成功持久化、失败清理、断线核对和重复提交保护。
- 小花园：从天气按钮扩展为可布置的小世界。首批新增花丛、蘑菇、水池、长椅、营火、萤火虫；原有小雨、安静、种树保留。

## 速度排查与改动边界

1. 基线真实生成21.537秒：人设7.461秒，开场白11.444秒，绘图请求12.407秒；后两项已并行。文本共报告399个推理token，需核对服务商非思考参数，不能凭参数名猜测兼容性。
2. 生成流已禁止代理压缩；聊天流尚未设置相同响应头。本轮补齐聊天SSE的no-cache/no-transform与禁止缓冲，并以隔离环境真实代理首块到达时间验证。
3. 页面应及时显示真实阶段和已等待时间，不展示伪造进度或“已完成”占位结果。不通过调低图像质量、提前ready或放宽阈值制造提速。
4. 模型参数变动须先核对官方支持范围，跑隔离质量/耗时验证后才启用。实际模型调用另备具体次数及预算；之前的测速授权已执行完，本轮不会自动重复付费调用。

已核对[千问官方思考模式文档](https://help.aliyun.com/zh/model-studio/deep-thinking)：qwen3.8-flash为混合思考，默认开启，可用enable_thinking=false切换。增加默认未设置的MODEL_ENABLE_THINKING配置，仅对白名单qwen3.8-flash的文本调用传参，不影响识别/绘图。蚂蚁MaaS是否透传及关闭思考后的质量仍须真实验证；验证前不修改开发环境的模型配置。

## 花园前后端契约

- 新增受控动作：plant_flower、grow_mushroom、add_pond、place_bench、light_campfire、release_fireflies。新增元素flower、mushroom、pond、bench、campfire、fireflies，缺省0，读取旧JSON时补默认值，保留已有元素和最近一步撤销记录；不删库、不重置用户花园。
- 花丛与蘑菇累加至画面可容纳的数量；水池、长椅、营火、萤火虫采用明确的添加动作，重复添加不凭空叠加。保留最近一步撤销语义，撤销包括新增元素。
- 三类工具：植物、景观、氛围。每个动作有不同的可见画面反馈，支持放大查看花园；纯视觉动效不依赖模型生成。
- 自然语言只识别明确单步请求，新增动作仍需用户确认后执行。当前花园对象写入模型上下文，避免伙伴不知道已经添加的物件；否定、普通讨论、多步指令不误触发。

## 验证顺序

技术方案→实现→后端状态/旧数据兼容/确认撤销测试→前端合同与交互测试→lint/typecheck/build→隔离Chrome桌面/手机全流程→必要的真实模型参数与耗时验证→用户体验反馈→PRD更新。

浏览器验收包含：创建入口、真实阶段显示、收藏/详情、三类工具、新物件可见、放大关闭、刷新恢复、撤销、聊天流首块即时到达、减少动态效果。原3020业务数据只读核对，新增操作放隔离库；用户8021/3021试用环境保持可用。

PRD待更新点：新的视觉方向、完整生成后进入的偏好、花园动作集合与边界、经过实测的速度结果。宠物对象已在实际试用中出现，而旧PRD写暂缓，作为范围待核对项保留，不擅自删除用户已有伙伴。

## 本轮实现与验收落点
