## 2. R6.1 开发前契约

新增 `backend/app/services/release_readiness.py` 与 `backend/scripts/check_release_readiness.py`。独立加载 Settings，不导入 app.main、数据库模块或路由，不启动服务、不迁移数据库、不调用网络。读取当前工作副本用于预检，不把报告当线上实际状态。

检查两部分：

- 配置：开发令牌／固定验证码是否禁用，是否使用模拟模型，模型地址是否 HTTPS，超时／重试是否有有效边界，生成额度是否开启，Agent 开关状态；数据库是否为磁盘存储。前端按生产加载优先级解析 .env、.env.production、.env.local、.env.production.local 与进程变量，只报告开发验证码提示／离线预览是否残留、NEXT_PUBLIC 中是否存在密钥类变量，不回显值。
- 代码：使用 AST 检查当前默认 MockSmsProvider、/uploads 静态挂载与历史 /claim 路由。命中已知开发实现为 blocked；没有命中也只能 pending，不能据此宣称替代实现安全。源文件缺失／不可解析为 pending。静态检查不能代替实际双账号权限验证。

当前源码已发现默认模拟短信和直接 /uploads 静态目录；后者需要在 R6.2 核实已知图片 URL 的匿名访问，并设计兼容已有 img 的鉴权链路。/claim 仍为开发历史认领入口，需要限制生产开放范围。此处先记录线索，不直接删除或关闭本地功能。

必须人工／环境验证的项目单列 pending：真实模型质量、成本上限、完整数据留存与删除、备份恢复、生产存储／部署／HTTPS、正式短信、跨账号权限和真实设备验收。配置正确不自动通过这些项目。

## 3. CLI 与报告契约

在项目根目录执行：

```sh
backend/.venv/bin/python backend/scripts/check_release_readiness.py --output .runtime/release-readiness.json
```

参数 `--output` 必填，拒绝覆盖现有文件，不自动建父目录。报告 UTF-8 JSON，文件权限 0600；根字段 `schema_version`、`checked_at`、`scope`、`ready_for_release`、`summary`、`checks`。每项含稳定 id、status（pass／blocked／pending）、中文 message、项目相对 source、next_step；不含配置原值、异常原文、用户资料或绝对配置路径。CLI 只打印状态计数与固定提示。

退出码：0 表示所有项通过；2 表示预检完成但有阻塞或待验（当前预期）；1 表示配置／读写失败。所有待验均关闭前，ready_for_release 必须 false；没有“强制通过”参数。错误返回固定 `error.code/message`，不输出可能含密钥的配置校验异常。

## 6. R6.2 权限与生产保护（开发前契约）

2026-09-21，用户要求优先完成 V1.1。R6.1 已提交 `34534a9`。先实现并验收本批，再推进恢复与整体验收；真实短信、模型质量和计费资源仍需后续具体方案与授权。

### 6.1 私人图片

保留数据库 image_path 和 `/uploads/{path}` 路径，不迁移或重命名既有图片。将直接 StaticFiles 挂载替换为 GET 鉴权路由：沿用 Bearer 会话；匿名 401，只有当前用户存在 ready 伙伴精确引用该相对路径才可读，否则 404。禁止绝对路径、反斜线、点段、越界符号链接和非图片类型，路径须位于配置 uploads 根目录。旧伙伴共用图片时各拥有者只依据本人引用访问。图片响应及鉴权失败禁止缓存；成功增加 nosniff 与 sandbox CSP。公开墙继续使用按发布关系验证的公开图片接口；队内图继续按成员关系验证，不公开原路径。

删除／撤下／退出之后的新请求重新检查权限；已经下载到设备的数据不能远程收回。不把已公开一次视为原始私人 URL 永久开放。

### 6.2 历史认领

保留 /auth/claim 迁移能力，默认关闭。新增 LEGACY_CLAIM_USER_ID，仅 development/test 且当前用户 ID 与该配置精确一致时允许现有幂等迁移。production 一律禁止；未经明确指定账号不认领。不新增前端认领按钮，不更改主库已有归属。旧迁移测试显式设置获准的测试用户，新增默认拒绝、他人拒绝、生产拒绝及拒绝后数据未变断言。

### 6.3 生产配置

新增 APP_ENV=development/test/production；默认 development 保持本地联调。production 启动时拒绝开发令牌、固定验证码、历史认领、模拟模型、不安全模型地址、无效超时／重试与内存库；当前仅有 mock 短信实现，因此 production 仍明确拒绝模拟短信，不能以设置一个虚假的“真实短信”标记绕过。开发配置不删除，正式开关不擅自开放。错误只输出字段类别，不输出实际输入值。

预检更新：静态目录移除后维持运行时待验；认领路由存在但已加保护时不能继续误报为无保护，静态扫描仍不替代测试。当前生产未部署，仍保留正式权限与短信验收待验。

### 6.4 验证

先以隔离库和合成图片复现匿名图片读取、普通账号认领，再验证修复。覆盖本人／他人／匿名、公开撤下、小队退出、共享旧图片、删除、路径穿越和符号链接；生产配置失败不得创建应用数据。前后端完整回归与类型／Lint／构建通过后，主库备份、校验数据不变、更新本地服务，浏览器检查既有图片与两个隔离账号。证据放阶段6/R6.2权限与生产保护。
