# H1 花园 Agent Demo 技术说明

日期：2026-09-21。用户已授权按候选方案先改并交付 demo；认可后才继续，不认可则删除 demo 并重新询问方向。

## 目标与范围

实现可操作的独立离线原型：模拟模型选择业务工具，运行器实际查询、持久化提议，用户确认后真实修改 demo 花园，模型再读取执行结果回应。模拟模型只覆盖推荐表达与有限同义词，不代表真实模型的自然语言能力。当前不进行付费调用，不接入现有伙伴数据。

本轮是独立 H1 试验，用户当前授权允许先交 demo；不视为原 S1 放行或正式前端 S2 全面启动。

## 技术适配

- 文件集中在 `demos/garden-agent/`，独立端口 `3030`，仅绑定 `127.0.0.1`。
- 复用本项目 `backend/.venv` 的 FastAPI / Uvicorn，不安装共享依赖；静态 HTML/CSS/JavaScript 作为验收界面，不替换正式 Next.js 前端。
- 只导入既有场景规则 `app.services.scene`，不导入正式应用入口、数据库或配置，不读取 `.env`。
- 独立 SQLite 位于 demo `.data/`；按浏览器会话隔离试验数据，保存运行、步骤、确认、花园和一次撤销。该隔离不宣称为正式账号系统。
- 实现可替换的模型适配接口、最多 3 轮模型 / 3 次工具 / 1 个待确认动作的限制。仅注册 `get_companion_context`、`get_garden_state`、`propose_garden_action`。
- 原型模拟响应短且立即完成，使用 JSON 请求与状态回读；实际步骤轨迹入库并可展开查看。未改正式 SSE 契约，后续接入真实模型再按方案实现流式适配。

## 关键规则

1. 未确认不改花园；拒绝无副作用；重复请求、确认和刷新不重复执行。
2. 参数严格校验；未知工具、越界参数、超预算立即停止。工具不能指定其他会话或伙伴。
3. 花园更新与执行结果同一事务保存；最终模型回复失败时按已保存结果确定性反馈，不重做动作。
4. 等待确认跨刷新与重启保留；中断的未完成运行启动时标记失败，已执行结果保留。
5. 新提议基于花园版本；重置/撤销后旧提议不可再次生效。撤销保持既有单步规则。
6. UI 明确标注离线模拟，并在手机与桌面按最新反馈展示淡紫淡粉渐变、奶白卡片、立体苹果伙伴、实时花园和确认卡片。

## 验证与交付

运行自动测试覆盖模型循环、参数/预算、确认与拒绝、幂等、状态过期、跨会话、重启恢复和回复失败。浏览器实际走确认、拒绝、撤销、刷新与手机布局。交付可打开地址、桌面/手机截图及验收记录；真实模型测试标记为待验。

## 撤回方式

若用户明确不认可，先停止 demo 进程，再删除 `demos/garden-agent/` 和本次 demo 的证据目录；同步移除导航与试用入口，将状态记录为已撤回，然后询问不满意之处。保留原项目代码、伙伴数据和之前的需求/架构分析。当前保留 demo 供用户试用，不自行触发删除或后续开发。

## 用户反馈增补：产品入口与体验身份

最新反馈要求只保留首页一个注册/登录按钮。独立 `account.html`、`account.css`、`account.js` 已移除；`dream.css` 实现梦幻首页，`access.js` 使用原生 dialog 管理合并入口、关闭、继续与退出。`account-session.js` 继续只保存离线体验身份，没有手机号或验证码流程，不用于后端鉴权。普通访问只显示产品说明与伙伴主视觉；进入体验后再展示原花园和聊天。用户数据、Cookie 绑定、数据库和业务接口不变。未来真实认证仍需独立验证，页面入口保持合并。
