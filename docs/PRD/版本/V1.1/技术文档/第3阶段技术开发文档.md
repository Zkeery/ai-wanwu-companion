## 1. 阶段范围与目标

在 R2 后端（账号隔离 + 多场景 API）之上，完成正式前端的温馨移动端体验。以手机优先，桌面同步适配；视觉统一为淡紫/淡粉/奶白。本阶段覆盖：登录入口与轻弹窗、生成与收藏、三个生活场景代表页、居住选择（独居/同住）、照料、拖拽与收纳。

本阶段交付：

1. 首页单一「注册 / 登录」入口与轻量弹窗（接 R2 auth API），登录后恢复当前账号数据。
2. 生成与收藏沿用现有链路，接入登录隔离后的接口（带令牌）。
3. 三场景代表页：家庭庭院、沙漠绿洲、林间营地，接 R2 living API（空间/物件/照料/收纳）。
4. 居住选择：独居（私人空间）与同住（共居空间 + 成员），伙伴当前位置切换。
5. 照料（care）、拖拽（move）、收纳（store/restore）与单步撤销，接 living 命令。
6. 全站淡紫/淡粉/奶白视觉改版，手机 360/390/430 + 桌面 768/1440，减少动态效果可用。

本阶段不做：真实短信平台接入（登录验证码用开发过渡，见第 3 节）、作品墙与小队（R5）、上线部署。

## 2. 视觉与设计系统

以 PRD 第 6 节为准，替代现有明亮潮玩风（`toy-theme.css`），新建或重写主题：

- 背景：淡紫至淡粉、奶白的低饱和渐变，局部柔光；避免整页深底和刺眼纯白。
- 文字：主文字深紫灰，辅助说明中深灰紫；渐变/发光不用于长段正文。
- 卡片：奶白或浅紫半透明圆角底、浅紫描边、柔和阴影；角色图用与角色协调的彩色背景。
- 主操作：淡紫粉渐变 + 深紫文字；次要操作低权重。
- 角色图：大幅、完整、立体质感小生物，保留物品特征；不新增可旋转 3D 系统。
- 标签：紧凑圆角，重要信息同时有文字，不只靠颜色。

布局与适配：

- 手机优先双列卡片，桌面 768/1440 逐步扩展为多列，不机械放大成一张巨屏手机页。
- 主触控区域 ≥44×44 CSS px；正文 14–16px 起，支持字体放大。
- 底部固定奶白/浅紫半透明导航，图标+中文短标签，当前项高亮；未交付功能不展示为可用入口。
- 遵循 `prefers-reduced-motion`，关闭非必要漂浮/呼吸/弹性动效后仍能完成全部流程。

代表页先做「收藏首页、场景选择与一个场景代表页」，确认后展开全页面；未交付页面（作品墙/小队）可做预览并明确标注，不冒充真实数据。

## 3. 登录与账号

- 首页只保留一个「注册 / 登录」按钮；点击后用轻弹窗承接（手机号 + 验证码），关闭后仍在原首页。登录后该入口变为「我的小世界」或账号入口，可退出。
- 登录流程接 R2：`POST /api/v1/auth/code`（发送验证码）→ `POST /api/v1/auth/login`（校验并签发令牌）→ 令牌存本地，后续请求带 `Authorization: Bearer <token>`；`POST /auth/logout` 登出。
- 令牌仅存浏览器本地，不进入 URL、日志或截图；请求失败 401 时回到未登录态并提示重新登录。
- 开发过渡（默认）：后端未接真实短信，登录弹窗在开发环境使用固定验证码（见 8.1）；或沿用 `DEV_AUTH_TOKEN` 直接进入。正式接入真实短信后移除固定码与开发令牌。
- 未登录访问任何数据接口都会被后端 401；前端在入口统一处理，不显示他人数据。

## 5. 多场景前端契约

对接 R2 living API，全部需带登录令牌。

### 5.1 空间与位置

- 进入场景选择页：`GET /living/spaces` 列出账号空间；`GET /characters/{id}/location` 取伙伴当前位置。
- 进入某场景：若伙伴在该场景已有私人空间则直接读取，否则 `POST /living/spaces`（`scene_type` + `mode=private` + `companion_id`）创建后进入；进入成功后才 `PUT /characters/{id}/location` 更新位置。
- 场景详情用 `GET /living/spaces/{space_id}` 快照：`scene_type`、`mode`、`revision`、`items[]`、`can_undo`。物件含 `kind`、`x/y`（0–1 归一化坐标，前端按场景容器换算像素）、`stored`、`growth_seconds`、`stage`（树：planted/growing/mature）、`growth_status`（mature/stored/growing/needs_care）、`care_remaining_seconds`。

### 5.2 命令与操作

`POST /living/spaces/{id}/actions`，body：`request_id`（前端生成 UUID）+ `expected_revision`（当前快照 revision）+ `command`。前端每次操作前用最新快照的 revision，冲突（409）时重新读取再提示。命令：

- `place(kind, x, y)`：放置物件（kind 按场景目录：home=树/长椅/花/蘑菇/水池/营火/萤火虫，desert=树/遮阴处，forest=树/坐垫）。
- `care(item_id)`：照料选中植物（仅已摆出的树）。
- `move(item_id, x, y)`：移动物件。
- `store(item_id)` / `restore(item_id, x, y)`：收纳 / 重新摆出。
- `undo()`：单步撤销最近一次放置/移动/收纳/摆出。

`request_id` 幂等：重发相同请求返回原回执；网络失败后可用同一 `request_id` 重试，不重复执行。

### 5.3 居住选择与成员

- 场景选择页提供「独自生活」（private，绑定当前伙伴）与「和我的其他伙伴同住」（shared + 成员）。
- 同住：`POST /living/spaces`（`mode=shared`）+ `POST /living/spaces/{id}/members`（`companion_id` 加入本账号其他伙伴）；`GET /living/spaces/{id}/members` 展示成员；`DELETE /living/spaces/{id}/members/{companion_id}` 移除。
- 切换居住方式保留离开的空间，不复制、不重复成长；所有成员读取同一份存档。

### 5.4 交互（移动端拖拽、照料、收纳）

- 拖拽与滚动区分：进入「布置模式」后选中物件再拖动，拖动中显示可放置反馈；超出边界或非法位置保留原位并提示。同时提供选中后的可点击移动（如方向/网格步进），避免只能靠精细拖拽。
- 拖动结束以归一化坐标提交 `move`；不保存屏幕像素。
- 照料：`growth_status === 'needs_care'` 的树显示「照料」按钮，执行 `care`；显示剩余照料时间或「等待照料」。
- 收纳：物件可「收纳」到所属场景收纳区，收纳区展示 `stored` 物件并可「摆出」；植物收纳期间暂停成长（后端已保证）。
- 撤销：`can_undo` 为真时显示撤销，作用于当前场景最近一步；切换场景不进入撤销历史。

## 6. 数据流与错误恢复

- 前端统一 `lib/api.ts`：所有请求带令牌；401 统一置为未登录态；网络超时/失败保留草稿并提示，可重新核对（重新读取）而非直接重试。
- 场景操作失败（冲突/网络）不静默覆盖：保留原画面，提示「场景已更新，请刷新后再试」或「请先核对已保存的结果」。
- 生成与收藏沿用现有 SSE 与恢复：状态不明确先核对，不重复发起付费请求。

## 10. 照片特征与性格驱动形象（先编手册，再开发）

编写日期：2026-09-21。来源：用户确认形象应参考原照片特征与性格，并要求开发前写好手册。本节属于当前创建链路增强，不启动 R4 场景 Agent 或跳过 R3 待办。编写时实现尚未开始，验证结果后续单独回填。

### 10.1 目标和边界

照片 → 一次识别对象及其可见特征 → 用户选择对象、核对对象名和特征 → 一次生成名字/性格/开场白 → 根据对象、特征、性格绘制形象 → 完整保存并进入收藏。

原图仍仅在内存中用于识别，不作为文件或数据库图像保存；保存的是选定对象的特征文字。图像模型仍是现有文生图接口，通过文字特征参考照片，不直接传原图，不承诺像素级还原。保留原有 3 次正常模型请求、1024×1024 形象、现有厂商和收费配置。真实模型验证仍待授权，不用 mock 宣称特征还原质量。

### 10.2 识别和用户确认

- 一次识别最多返回 5 个对象，每个对象包含 `label` 和 `visual_features`。
- `visual_features` 是不超过 500 字的描述，覆盖可见颜色、形状、材质/纹理、显著标记；只写该对象，不带入其他对象、背景私人信息、人脸身份或不可见推断。无可靠信息时为空，不编造。
- 解析器接受旧的仅 label 结果并给空特征；特征类型错误或超长则校验失败，不静默截断误导用户。
- 对象确认页显示可编辑的「照片里的特征」。切换对象时一起切换特征；改对象名称时提示核对特征，避免错认后继续使用原物件特征。
- 旧照片无特征时允许用户补充，明确提示未保存特征，不能宣称从旧原图恢复了细节。
- 用户输入的描述作为数据处理，不作为模型系统指令；提示词明确保留事实、忽略描述中要求改变规则或泄露信息的文字。

### 10.3 数据和接口兼容

- `objects.visual_features`：TEXT，非空，默认空串。旧记录只补空值，不回填虚构特征。
- `characters.generation_brief_json`：可空 TEXT，保存成功生成使用的版本、对象名、确认特征、性格和生成时名字，便于复核形象来源；旧记录为空。该字段不写日志。
- 采用启动时可重复执行的加列迁移，先检查列是否存在；不删除/重建用户表。真实数据库迁移前备份，迁移后核对旧记录与图片不变。
- `PhotoOut.objects[]` 新增 `visual_features`（默认空串）；旧客户端忽略该增量字段。
- `POST /characters` 新增可选 `visual_features`，最多 500 字；省略时使用对象已有特征，显式空串表示清除特征。无权限、无对象、非法输入在模型调用前拒绝；纠正内容在原角色预留事务中保存。

## 15. 三场景自由拖拽布置（先编手册，再开发）

### 15.1 本轮范围

### 15.2 用户流程与交互状态

1. 默认浏览模式可滚动页面，点击物件可照料或收纳；点击「布置场景」进入布置模式，按钮变为「完成布置」。
2. 布置模式先点选一个物件，再拖动选中物件；仅选中物件关闭浏览器触摸滚动，其余区域仍可滚动。提供上下左右各 5% 的方向按钮，保留点击场景空位移动，兼顾键盘及精细操作困难的用户。
3. 超过 6 CSS px 才认定拖动；拖动仅在前端预览，松手才提交一次 move，按下不移动／取消／位置未变化不提交。显示「松手保存位置」或「超出布置范围，松手回到原位」，不把越界坐标静默截到边缘。
4. Escape、pointercancel、丢失指针捕获、切换空间、拖动期间尺寸或服务端版本变化均取消预览，不写入。不同空间的迟到响应不能改写当前页面。
5. 保存期间锁定其他写操作，显示保存中；成功采用服务端快照，保留单步撤销。失败沿用错误提示＋读取最新状态，不自动重放；读取失败时必须先核对场景。

### 15.3 坐标与接口

- 沿用 0–1 的场景坐标，精度为两位小数，不保存屏幕像素。显示时横向留 52px、纵向留 48px 内边距，确保边缘物件完整可见；手机／桌面使用相同归一化位置。
- 拖动保留手指与物件中心的相对偏移，不在按下时跳动；转换后的中心越过 0–1 时判为不可放置。尺寸不足或非有限数值不提交。
- 复用 `api.living.action(space.id, request_id, revision, {action: 'move', item_id, x, y})`；响应为 `LivingSpace`，错误遵循现有 `{error: {code, message}}`。请求 ID 每个实际写操作生成一次。
- 沿用现有允许物件重叠的规则，不新增未经确认的碰撞占地限制；选中物件提高显示层级，并提供「选择物件」下拉列表，保证重叠物件仍可通过触摸／键盘选中移动。物件 ID、成长、照料、独居／同住语义保持现有契约。

## 17. R3 阻塞修复：场景存档统一与庭院氛围

本节先于实现编写。范围限于 R3 复验发现的问题，不启动 R4。

### 17.1 同一份场景数据

聊天页存在生活场景时，展示并操作伙伴当前所在的空间；未选择位置时优先使用其家庭庭院。旧接口保留响应字段，附带生活场景快照，旧花园仅作为尚未建立生活空间时的兼容入口。聊天上下文读取同一空间，提议绑定空间、版本和位置代次；切换位置、离开共居或空间变更后，过期提议不能执行。

建立家庭庭院时导入旧花园；已有庭院按各物件种类补足旧存档数量，已有物件的位置、收纳和成长不覆盖。旧原文及撤销记录保留，并记录一次性导入标记，重启或重复进入不重复导入。导入和位置变更在数据库事务内完成。旧花园撤销不跨越导入边界，新场景从自己的撤销记录继续。

浏览器复查补充：旧导入和聊天新增物件优先使用九个分散空位，避免少量物件默认叠在一起；不改变已经保存的位置。场景工具新增物件采用相同空位策略，空位用尽后仍允许叠放并可从选择器选中，不引入新的数量限制。

### 17.2 雨声与安静

家庭庭院增加小雨、放晴和安静操作，氛围和物件使用同一版本控制及请求回执。氛围可撤销最近一步；照料仍不覆盖布置撤销。声音必须由用户点「开启声音」后在本机播放，离页关闭，不自动播放。沙漠和林间不开放庭院天气操作。

旧场景数据采用显式版本兼容转换，不能把缺字段的损坏存档当作正常默认值修复。历史回执继续可读。
