# 前端第5阶段技术开发文档

职责：**前端**。接口、持久化和匹配规则以[第5阶段技术开发文档](第5阶段技术开发文档.md)为准。2026-09-21 先编写本手册，再开发 R5.1；随后先补第5节再完成 R5.2 作品墙。R5.3 好友小队仍在 V1.1 范围，尚未开发。

## 1. 页面与视觉

新增 `/themes` 主题选择页：淡紫／淡粉背景、暖白卡片、水果主题插画和清楚的“拍一份水果，遇见独特伙伴”说明。插画仅作主题示意，不冒充生成作品。桌面并列展示主题和玩法说明，手机单列；使用 Lucide 功能图标、有文字的按钮、可见焦点。

已登录收藏和创建页提供主题入口，未登录首页继续只有注册／登录按钮。主题页允许浏览说明，开始创作仍复用登录弹窗。主题入口跳转 `/companions/new?theme=fruit`，同时保留自由拍摄。非法主题给明确提示，不悄悄换成自由创作。

## 2. 完整流程

选择主题 → 上传 → 识别并核对类别 → 符合时自动生成 → 结果显示主题和“已加入我的收藏”，公开状态在分享预览中核对 → 回到收藏可见主题标签。主题只约束题材，不要求大家拍同一个水果，也不按名字套模板。

主对象不符／类别未知时，保留识别结果与候选，停止生成；提供“换张照片”“选择其他对象”“改为自由创作”。自由切换只改变下一次生成归属，不重新识别、不自动发起生成。名称被修改而失去类别确认时同样停下，引导保留识别名称或自由创作。

## 3. 状态与恢复

主题、自由切换和原请求键随创建草稿保存。刷新从服务器查询照片与伙伴；完成结果的主题以服务器为准。旧草稿没有主题时正常恢复。恢复旧草稿优先于新 URL 主题，给出说明并允许在结果／明确失败后重新开始；不丢失正在运行的任务。

HTTP 409 theme_mismatch 是明确拒绝，回对象选择步骤；网络中断／5xx 保持“核对结果”，不能自动重试。加载失败可重试主题目录；空目录不能假装已经选好主题。照片处理与生成时禁用主题切换，避免请求归属串用。

## 4. 验证

自动化覆盖主题目录错误／重试、创建请求携带主题、类别不符不生成、切换自由、恢复保持主题、旧数据兼容与结果私有提示。类型检查、Lint、生产构建均需通过。浏览器验证登录→主题→模拟生成→收藏→刷新，并检查 360、390、430、768、1440px、键盘焦点与无横向溢出。

模拟图不能证明真实生成质量；真实分类准确率、真实手机及视觉满意度继续待验。最终证据、闸门与测试数量记录在阶段 5 验收目录，不提前标为完成。

## R5.1 按钮可用性修复（2026-09-21，先补契约再修改）

复现：离线服务仅识别合成色块，普通照片可能返回杯子；水果主题因此不能生成，但按钮仍亮着，重复点击只显示原错误。修复要求：在生成按钮旁解释题材不符，按钮禁用直到选到水果或明确改为自由创作。自由切换入口靠近生成按钮，刷新后同样可见。离线构建提供“模拟生成伙伴”按钮，使用固定合成水果输入走真实本地上传、保存、SSE 与收藏流程，明确为模拟、不代表真实照片识别；正式构建不显示该入口。沿用现有后端主题检查与额度规则，不绕过校验，不更换模型，不使用付费服务。

修复结果：创建组件 32/32、类型／Lint／构建通过；桌面一键模拟与手机主题拒绝转自由创作均走通。真实模型 0 次。详见[按钮修复与验证](../验收证据/阶段5/模拟生成按钮修复/修复与验证报告.md)。

## 5. R5.2 共同作品墙（2026-09-21，开发前契约）

先完成本节与配套后端第 6 节，再开始开发。沿用淡紫、浅粉与奶白。R5.3 小队和点赞／排行／评论本轮不实现。

### 5.1 页面与入口

/themes 保留主题目录，增加“看看作品墙”。/themes/{theme_id} 为公开作品墙：主题图标、大标题、玩法说明、实际公开数量、“参加创作”，随后手机双列作品卡片；320px／字体放大可单列。图片 contain 保留角色全貌，长名可换行；缺图有明确占位。空状态提示“成为第一位分享的人”，不填假热度。列表分页加载并按公开 ID 去重。

点击作品打开页面内详情弹窗，展示完整图片、名字、介绍、作者和主题；关闭回列表保留滚动位置。详情重新从公开 API 读取，撤下后显示不可用与重新加载。可通过 /themes/{theme_id}?work={publication_id} 打开同一详情。弹窗有标题、关闭、Esc 与焦点管理。

私人收藏卡片旁为有主题且 ready 的伙伴提供“分享作品”入口；创建结果也提供入口。点击打开发布预览，显示将公开的完整字段，作者填写展示名（默认“小小创作者”）。明确只公开角色图、名字、简短介绍、主题和展示名，不公开聊天、记忆、原照片与私人场景。只有点击“确认发布”才写入。发布后可查看作品墙、撤下；撤下前说明保留收藏。改名后公共展示同步。普通收藏卡片继续进入聊天，分享按钮不嵌套在链接内部。

### 5.2 状态与异常

加载失败可重试，发布／撤下期间锁定按钮防重复。写入结果不明时保留弹窗和展示名，先查询服务器核对状态，未核对成功不自动重复写入；预览和请求返回结果需结构校验。退出登录／切换用户时不复用其他账号的预览；服务端检查归属。公开页面不要求登录，参加创作继续使用现有登录弹层。

已加载的浏览器内容不能远程抹除；撤下后所有新读取均不得返回公开作品。列表重新加载清除过期数量与作品，详情不使用旧卡片数据假装仍存在。

### 5.3 验证

覆盖预览不写入、确认／取消、重复点击、发布状态核对、撤下保留收藏、加载失败与重试、详情撤下提示、空列表与真实数量、响应格式非法、长名和缺图。运行相关单元测试与全量回归、类型／Lint／生产构建；浏览器验证桌面及 360/390/430/768/1440px，双账号查看／作者撤下，检查弹窗焦点与返回位置。证据写阶段5/R5.2作品墙/，不将模拟角色认作真实质量验收。

## 6. R5.3 好友主题小队（2026-09-21，开发前契约）

先补本节与后端第7节，再开发。入口 /teams，新增创建弹窗、邀请页 /teams/join、队伍页 /teams/{id}；从主题目录与作品墙提供“小队”入口。视觉延续淡紫粉暖色和角色卡片。

- 建队：填写名字、展示名，固定水果主题；说明只有确认加入的成员能看队内作品。保存 request_id 和表单到本标签页草稿，结果不确定先查询队伍，避免重复创建。
- 邀请：发起人在队伍页主动生成链接并复制，显示“新链接会使旧链接失效”；可停用。链接使用 hash fragment，捕获后从地址栏移除并放 sessionStorage 以支持登录／刷新。令牌不进入截图；不自动发消息。响应丢失时可由发起人明确重建链接。
- 加入：先显示邀请主题、队伍名和可见范围；未登录先打开既有登录弹窗；填写展示名并确认后才加入。失效、已加入和解散均给明确信息。
- 成员页：显示成员、各自提交数、实际作品；提交仅列本人该主题 ready 的收藏，并预览选中伙伴再确认。没合格伙伴可“去创造伙伴”；生成完成后仍须返回小队主动提交。公共作品墙发布状态不受小队动作影响。
- 队内图像通过携带认证的 fetch 下载为 blob URL，卸载撤销 URL；不把登录 token 塞入 img URL。失败给占位提示，非成员不回退到原存储地址。
- 作者可撤回自己的提交；普通成员退出／发起人解散先二次确认并明确保留收藏。重复点击锁定，失败保留输入；写入结果不明先刷新队伍状态，未核对成功前禁用再次写入。所有错误可重新核对。
- 验证桌面与五种移动宽度、登录邀请恢复、创建／加入／提交／撤回／退出／解散全流程、不同账号越权、网络错误与重试、键盘焦点和图像加载。测试隔离环境无真实模型／短信。证据放阶段5/R5.3好友小队。

## 7. 彩色系视觉调整（2026-09-21，开发前方案）

用户提供 cozy-cute-reference.html，并要求“非常吸睛”。本轮是现有界面的视觉调整，先更新 PRD 与本节，再实施；不增加后端接口或新业务阶段。

- 参考来源：http://127.0.0.1:8736/outputs/cozy-cute-reference.html 。以其中 Happy Cat Cafe 的奶油纸底、珊瑚红重点及多色角色为基准，结合其他参考的杏黄、薄荷绿、雾紫和天蓝。只参考配色、层次和气氛，不复制第三方插画。
- 色板：底色 #FCF7ED、正文 #594A40、辅助字 #705e50；重点珊瑚 #EE8C87、杏黄 #F6D779、薄荷 #CEE3CF、雾紫 #D8CCE8、天蓝 #C8E1ED。浅彩色块搭配深文字，主操作使用珊瑚色，避免满屏同一种紫色。
- 应用范围：首页欢迎区／收藏卡片、创建页、主题页、作品墙、好友小队、登录和提交弹窗、聊天与场景控件。保留现有流程、生成图片、手机双列卡片以及场景坐标规则。
- 吸睛方式：首页大标题和珊瑚重点、彩色分区、圆角卡片和暖色偏移阴影；装饰只放在空白区，不能挡文字或操作。小队成员和卡片交替使用黄／绿／紫色。
- 实现：在现有 warm-theme.css 中更新主题颜色并集中维护新色板，不增加第四层全局主题文件；必要时只给现有展示元素补充装饰类。场景物件 hover/active 不修改定位 transform，不引入持续晃动。
- 验证：首页、主题、小队、创建与弹窗的桌面／手机截图；360/390/430/768/1440px 溢出检查、主操作和正文对比、已有场景定位回归；运行前端测试、类型／Lint／构建。纯视觉改动不新增复述 CSS 的测试，不调用付费模型，不修改数据库。
- 证据：阶段5/彩色系视觉调整/。工程检查和用户视觉满意度分别记录。

## 8. 浓彩背景调整（2026-09-21，开发前方案）

验证桌面、手机首页及主题／创建入口，五种宽度无溢出；检查底色最暗端点与正文对比，完成类型、Lint、生产构建。纯背景样式不新增测试；工程检查与审美反馈分别记录。证据存阶段5/浓彩背景调整/，调整先不提交。
