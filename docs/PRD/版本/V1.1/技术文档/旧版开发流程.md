## 1. 如何使用这套流程

新版阶段统一标记为 **V1.1-S1～V1.1-S6**。下文“第 1 阶段”指 V1.1-S1，与旧版“后端 MVP 第 1 阶段”“前端第 1 阶段”分别管理。

已有照片创建、角色收藏、聊天、手动记忆和九类花园操作继续复用；旧浅色页面的功能逻辑保留，外观按 PRD 第 6 节重做。已通过的测试成为回归基线，历史验证不自动算作新版阶段通过。

每阶段遵循同一顺序：

1. 核对 PRD、上阶段证据与当前代码差异。
2. 先写本阶段技术手册，确定输入输出、兼容规则、异常、测试及通过条件。
3. 按手册开发本阶段范围内的代码。
4. 完成本地测试、构建、必要的浏览器与数据恢复检查。
5. 完成本阶段所需的真实模型或外部服务验收；涉及付费调用时，在具体方案准备完成后取得对应授权。
6. 交付证据包，更新 README 和项目状态，逐条填写阶段闸门。
7. 只有本阶段验收关闭后，才实施下一阶段；提交代码按用户指令处理，不以 commit 代替验收。

用户目前选择“暂不调用，先看新版页面”。因此可以完成技术文档与免费本地开发验证，不能自动运行已准备的付费测试、启用候选模型参数或宣布真实提速通过。

## 4. 第 1 阶段为什么先做这三项

三项来自 PRD 第 11 节原有实现缺口，本轮已局部修复并用确定性用例验证。下表保留修复前影响及目标：

| 缺口 | 不修复的实际影响 | 第 1 阶段结果 |
| --- | --- | --- |
| 识别候选没有后端数量上限 | 模型返回多少，页面可能展示多少，与最多 5 个的产品规则不符 | 新结果与重新读取结果最多 5 个，保留旧对象及已有角色关联 |
| 长度限制主要在页面 | 绕过页面的请求可以写入超长内容或触发模型调用 | 后端在写库/调用模型前拦截；页面与接口按同一长度口径处理 |
| 树木数量持续累加、画面最多 7 棵 | 点击仍显示成功，却没有对应新增树木 | 新增最多 7 棵；上限不继续累加；旧超限存档保留并明确显示 |

这一阶段不重新设计角色、不改模型、不新增付费调用，也不删除已有数据。手册先于开发完成，本轮实现及免费证据已交付，整体放行仍受真实冒烟闸门约束。

## 6. 验收顺序与当前暂停点

“手册完成”“本地检查通过”“阶段验收通过”分别记录。

- 手册完成：方案、测试和验收标准已可审查，不代表代码已改。
- 本地检查通过：本阶段代码与免费检查完成，仍要列出未完成的真实模型或用户验收项。
- 阶段验收通过：项目规则要求的闸门全部满足，才允许正式实施下一阶段。

第 1 阶段涉及识别结果处理和聊天入口，保留基本真实模型冒烟门槛。现有历史实测不能自动代替修改后的正常链路验证。用户暂停付费期间，本地工作可以推进到可审查状态，真实冒烟仍标“待验”，不宣布 S1 整体完成。后续阶段的文档可以准备，后续业务实现仍受前一阶段闸门约束。

S1 的基本冒烟只检查修改后的正常链路；S3 另做全面速度和质量评估，两者不是相互等待的依赖关系。S1 不调用旧的付费脚本凑验收，不自动重用此前已完成批次的预算。
