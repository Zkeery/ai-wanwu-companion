# 第5阶段技术开发文档

## 1. 范围与实施顺序

| 批次 | 后端内容 | 当前状态 |
| --- | --- | --- |
| R5.1 | 预设主题、识别类别、主题生成、私人收藏与恢复 | 工程与离线验证通过，真实质量待验 |
| R5.2 | 公开预览、主动发布、撤回、私有字段隔离、删除联动 | 工程与离线验证通过，详见第6节 |
| R5.3 | 固定主题小队、邀请加入、成员提交／撤回、退出／解散 | 后续实施，不算本轮完成 |

第一项预设主题为“一份水果”：苹果、橘子、香蕉等不同水果均可；自由拍摄入口保留。不新增排行榜、评论、点赞、奖励或定时活动。R5.1 无公开接口；R5.2 的公开接口见第6节，始终由作者主动发布。

## 2. 数据与兼容

增量增加 `photos.theme_id`、`characters.theme_id`（可空）以及 `objects.category`（默认 `unknown`）。主题目录为服务端固定常量，主题 ID `fruit`。不依据生成后的名字推断主题，也不重写旧伙伴。旧记录为空主题可继续创建、改名、聊天、纠正与再创作。

原照片仍不落盘。识别类别来自现有同一次视觉请求，枚举 `fruit / plant / object / other / unknown`，没有类别的旧输出按 unknown 处理；非法枚举拒绝。构思仍基于真实照片特征，不将主题当作改变物品的指令。

## 3. 接口契约

| 接口 | 增量 | 响应与错误 |
| --- | --- | --- |
| `GET /api/v1/themes` | 公共固定目录，无个人数据 | `[{id,title,description,category}]` |
| `POST /api/v1/photos` | 可选 Form `theme_id` | `PhotoOut` 增加 theme_id；对象增加 category；未知主题 422 |
| 照片查询、识别回执、纠正副本 | 返回并保存主题 | 沿用现有归属校验与回执状态 |
| `POST /api/v1/characters` | 可选 `free_creation: boolean=false` | 沿用 SSE；done 的 CharacterOut 增加 theme_id；主题不符／无法确认时在扣额度前返回 409 `theme_mismatch` |
| 伙伴列表、详情、改名、再创作回执 | 返回 theme_id | 旧字段保持不变 |

`theme_id` 进入上传幂等摘要；同一请求键不能更换照片或主题。自由拍摄不改变旧摘要算法，兼容已有回执。字符空白主题、非法类型不得静默降为自由拍摄。

## 4. 匹配、纠正和恢复

水果主题只接受已识别为 fruit 的候选。主对象不符时前端停在选择对象步骤，可换其他候选、换照片或明确选择自由创作；后端重复校验。unknown 不伪装成符合主题。主题模式下修改对象名称后不能沿用旧类别，返回无法核对提示；改选已识别候选或切换自由创作再提交。不用字符串包含“苹果”判断水果，避免“苹果电脑”等误判。

free_creation 只决定本次伙伴的主题为空，不修改照片和已完成伙伴；由回执恢复该选择。纠正副本继承照片主题；已切换自由创作的结果继续纠正仍保持自由选择。再创作继承原伙伴主题，不重新套用原照片主题。失败重试、额度预留／返还沿用 R4；主题拒绝不调用绘图、不创建生成中伙伴、不扣额度。

## 5. 验证与闸门

需要覆盖：水果匹配、非水果／未知／改名拒绝、自由切换、候选选择、主题幂等冲突、越权读取、成功 SSE／失败重试／刷新恢复、再创作主题继承、旧库副本两次升级及服务重启持久化。回归全部后端测试，前端验证见配套手册。

真实类别准确度和独特形象质量需要后续真实样例；本轮只运行明确标识的模拟验证，不调用付费模型、不替换模型。已有 R3/R4 待验闸门保留。验收证据放在 `../验收证据/阶段5/`，完成后补结果，不提前填通过。

## R5.1 按钮可用性修复（2026-09-21，先补契约再修改）

复现：离线服务仅识别合成色块，普通照片可能返回杯子；水果主题因此不能生成，但按钮仍亮着，重复点击只显示原错误。修复要求：在生成按钮旁解释题材不符，按钮禁用直到选到水果或明确改为自由创作。自由切换入口靠近生成按钮，刷新后同样可见。离线构建提供“模拟生成伙伴”按钮，使用固定合成水果输入走真实本地上传、保存、SSE 与收藏流程，明确为模拟、不代表真实照片识别；正式构建不显示该入口。沿用现有后端主题检查与额度规则，不绕过校验，不更换模型，不使用付费服务。

修复结果：创建组件 32/32、类型／Lint／构建通过；桌面一键模拟与手机主题拒绝转自由创作均走通。真实模型 0 次。详见[按钮修复与验证](../验收证据/阶段5/模拟生成按钮修复/修复与验证报告.md)。

## 6. R5.2 共同作品墙（2026-09-21，开发前契约）

范围对应 PRD F09.2。实现主题作品列表／详情、作者预览与主动发布／撤下、删除联动。R5.3 小队本轮不开发；不新增点赞、排行、评论、奖励，不调用模型。

### 6.1 数据与公开边界

新增 theme_publications 表：UUID id、唯一 character_id（外键 ON DELETE CASCADE）、author_name（1–20 字）、published_at。主题与作者归属从 Character 读取，不接受请求指定 owner_id/theme_id；只有本人、ready、有已知主题及有效角色图的伙伴可发布。旧伙伴不会自动公开，新增空表不改旧行。撤下删除发布关系，收藏不变；重新发布生成新公开 ID。重复发布返回同一记录，不刷发布时间；数据库唯一约束处理并发。

公开 DTO 只返回 id、theme_id、name、introduction（人设前 160 字）、author_name、image_url、published_at。不返回手机号、内部账号／伙伴／照片 ID、聊天、记忆、照片特征、原图路径、私人场景。名字与介绍实时读取伙伴，改名自动一致。展示名由作者在预览中填写，默认“小小创作者”，不从手机号生成；禁空白、控制字符和手机号格式。公开图片仅通过 publication ID 的专用路由提供，撤下或删除后该路由返回 404；不暴露原存储路径。JSON 与图片设 Cache-Control: no-store。已被别人保存的公开副本无法回收，预览提示公开含义。

### 6.2 接口

所有路径位于 /api/v1；错误统一为 error.code/message，不返回堆栈。

| 方法与路径 | 请求 | 响应／规则 |
| --- | --- | --- |
| GET /themes/{theme_id}/works | offset≥0，limit 1–50，默认 20 | items、total、next_offset；按 published_at DESC/id DESC，匿名可读 |
| GET /themes/{theme_id}/works/{publication_id} | 无 | 公开 DTO；主题不符／撤下／删除 404 |
| GET /themes/{theme_id}/works/{publication_id}/image | 无 | 公开角色图片；路径限制在上传目录内，无存储路径回显 |
| GET /wall/characters/{character_id} | 登录 | 本人发布预览：name、introduction、theme_id、image_url、author_name、publication_id；非本人 404 |
| PUT /wall/characters/{character_id} | author_name | 作者明确确认后发布，返回预览状态；未知字段拒绝，重复不重复卡片 |
| DELETE /wall/characters/{character_id} | 登录 | 撤下 204，重复也 204；非本人 404 |

预览不写库。free/旧无主题、生成中／失败、缺图返回 409 not_publishable。删除伙伴沿用现有 API，外键级联移除发布；不改变原收藏和聊天 API 权限。小范围列表采用 offset 分页，动态增删后可刷新核对，前端合并时去重。不把公开链接作为私人伙伴入口。

### 6.3 验证与开放

覆盖默认私有、预览不发布、作者确认、重复／并发发布、分页排序／总数、匿名公开字段、跨账号拒绝发布撤下和私人读取、改名同步、撤下及删除图片路由失效、路径穿越、非法展示名、重启持久化与旧库升级。离线双账号浏览器验证完整流程；用户真实伙伴不由 Agent 发布。主库备份后只新增空表，原数据核对不变。真实模型质量不属于本轮新增能力验证，已有待验保留。部署／正式短信和对外上线仍在 R6。

## 7. R5.3 好友主题小队（2026-09-21，开发前契约）

对应 PRD F09.3：固定主题建队、邀请预览／确认加入、成员作品、主动提交／撤回、退出／解散。邀请不自动发送，小队不自动公开；不开发群聊、排行榜或支付。

### 7.1 数据与权限

新增 teams（UUID、发起人、名称、固定 theme_id、active/dissolved、邀请哈希、创建时间）、team_members（小队／账号唯一、独立成员展示 ID、展示名）、team_submissions（小队／伙伴唯一、提交 UUID、作者、时间）。提交关联成员的复合外键，退出删除成员时级联删除其队内提交；伙伴删除同样级联移除提交。解散事务内清除成员／提交并禁用邀请，保留小队墓碑，保证旧请求不会重建。私人伙伴及主题作品墙不受影响。

所有成员页、成员列表、提交图像都在后端验证当前成员身份；非成员统一 404。发起人只能使邀请失效、生成新邀请或解散，不能修改成员伙伴、访问聊天或代为公开。发起人不直接退出，页面引导解散。提交只能选择本人、ready、相同主题且有图的伙伴；同一伙伴重复提交不产生重复卡片。

邀请为随机 32 字节令牌，仅存 SHA-256 哈希。通过 /teams/join#invite=... 分享，页面将令牌放 JSON 请求体，避免令牌进入访问日志／Referer；不在对话、截图和报告回显令牌。只有拿到有效邀请的人能预览小队名称、主题、发起人展示名和人数，不返回成员作品或账号。新邀请立即使旧邀请失效；停用不移除已加入成员。重启后邀请仍有效。邀请属于可撤销加入凭据，不能作为读取队内图片的凭据。

### 7.2 接口（/api/v1）

| 方法与路径 | 输入与输出 |
| --- | --- |
| GET /teams | 登录；只列本人已加入且 active 的队伍 |
| POST /teams | request_id UUID、title 1–30字、theme_id、display_name 1–20字；建立队伍与发起人成员。request_id 用作 team_id，同一用户同一输入重试不重复建队，输入变化 409 |
| GET /teams/{id} | 成员；队伍信息、成员与提交白名单；不返回内部用户 ID、私人伙伴 ID、存储路径 |
| POST /teams/{id}/invitation | 发起人；生成新链接令牌并轮换旧令牌，只在这次响应返回明文 |
| DELETE /teams/{id}/invitation | 发起人；邀请失效，重复可安全执行 |
| POST /team-invitations/preview | token；最小邀请预览，失效／解散 410 |
| POST /team-invitations/join | 登录、token、display_name；确认加入，已加入返回 already_member |
| PUT /teams/{id}/submissions/{character_id} | 成员；仅自己的合格伙伴，重复不重复提交 |
| DELETE /teams/{id}/submissions/{submission_id} | 成员；仅作者，重复安全，不删收藏 |
| GET /teams/{id}/submissions/{submission_id}/image | 成员身份校验后返回角色图片，不接受 URL 中的登录 token |
| DELETE /teams/{id}/membership | 非发起人成员退出，事务内清除其提交；再次退出可安全执行 |
| DELETE /teams/{id} | 发起人解散；重复安全，普通成员拒绝 |

成员 DTO 返回独立 ID、展示名、is_me、is_creator、提交数量；作品只返回提交 ID、角色名字、介绍、作者展示名、is_mine、授权图片路由、时间。角色名字实时读取保证改名同步。读写与离队／解散采用 SQLite BEGIN IMMEDIATE 事务串行化，避免检查权限后被并发退出的竞态。统一 error.code/message；成员数据与图片 no-store。展示名沿用作品墙的空白、控制字符、手机号校验。

### 7.3 验证
