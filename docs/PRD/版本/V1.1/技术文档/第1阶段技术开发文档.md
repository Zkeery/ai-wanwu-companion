## 1. 阶段范围与文件

新增 `backend/app/living/`：`rules.py` 保存结构化状态与规则，`store.py` 保存数据库事务与读取。新增 `tests/test_living.py` 和免费复核脚本 `scripts/check_living.py`。复用现有依赖，无新增服务端口。证据归档在 `../验收证据/阶段1/`。

本阶段支持内部服务入口和自动化验证，不新增产品页面。账号认证、成员管理、伙伴迁移、图片资产、真实场景 Agent 和正式前端分别由后续阶段接入。本阶段的 owner_id 必须由未来的可信会话适配层提供，不能接收浏览器任意声明的用户 ID；内部归属检查不等于已具备正式登录隔离。

## 2. 数据与状态

- 场景目录：`home` 家庭庭院、`desert` 沙漠绿洲、`forest` 林间营地。每类允许的物件清单集中维护，R1 的验证资产为树苗、庭院长椅、沙漠遮阴处和林间坐垫；完整美术和更多动作随代表页补齐。
- `living_spaces`：稳定 UUID、owner_id、场景类型、`private/shared`、私人伙伴标识（仅 private 必填）、revision、结构化 state_json、最近一次可撤销操作。私人空间在同一账号/伙伴/场景下唯一；共居空间与伙伴生命周期分离。
- `living_receipts`：space_id + request_id 唯一，记录规范化命令摘要和当次结果，随空间删除；R1 不提供空间删除入口。重发相同请求返回原回执，不再次执行；同一 ID 换参数返回冲突。
- 物件：稳定 UUID、kind、归属空间、0–1 的归一化坐标、stored、growth_seconds、settled_at、cared_until。坐标有限且有边界，后续前端按场景坐标转换，不存屏幕像素。
- 时间全部采用服务端 UTC 秒。普通树苗累计 259200 秒有效成长成熟；阶段为 planted/growing/mature。家具无成长状态。数据库 JSON 读写须结构校验，损坏时明确报错，不用空场景覆盖。已保存状态、物件和回执必须包含本版本完整字段；创建新对象可使用默认值，读取已有存档不得用默认值补齐丢失字段。

## 3. 成长、收纳和撤销规则

每次成功照料将 cared_until 更新到当前时间 + 86400 秒，不把原到期时间再加一天。成长增量 = max(0, min(当前时间, cared_until) − settled_at)，只对未收纳且未成熟植物生效，并封顶 259200 秒。每次操作先按旧状态结算，再应用本次动作；离线与在线同一算法，没有后台模型调用。

读取按当前时间投影，不改变 revision；重复读取不多算。操作会保存结算后的状态；写入时遇到早于已保存时间的时钟值则拒绝，防止倒退。服务端时钟由模块内部注入，只供测试替换，不属于用户请求参数。

收纳先结算到当前时刻，再标记 stored；暂停期间不累计。摆出保留原 ID 与进度，照料过期则等待照料。移动不重置成长或照料状态。收纳属于原场景，不复制到另一空间。R1 只校验坐标边界；物件占地和重叠由 R3 资产设计细化。

单步撤销覆盖放置、移动、收纳和摆出。照料及时间流逝不属于布置撤销，不能用撤销回滚或延长照料有效期。撤销先结算成长，再恢复上一步的位置/收纳状态，不倒退成长、不补算收纳时段；新增物件的撤销移除该新物件，其他数据保留。并发更新或过期版本返回冲突，由调用方重新读取再决定。

## 4. 内部服务契约

| 方法 | 输入 | 输出 |
| --- | --- | --- |
| create_space | owner_id、space_id、scene_type、mode、private companion_id | 完整空间快照；相同 ID/相同内容重复创建返回已有状态，内容不同返回冲突 |
| read_space | owner_id、space_id | revision、场景与投影物件、阶段、照料状态 |
| execute | owner_id、space_id、request_id、expected_revision、command | 当次操作后的空间快照；重复相同请求返回原快照 |

command 支持 `place(kind,x,y)`、`care(item_id)`、`move(item_id,x,y)`、`store(item_id)`、`restore(item_id,x,y)`、`undo()`。所有输入拒绝多余字段、非法枚举、非有限坐标与缺少参数。禁止从命令传入时钟、owner、growth 或 revision 等服务端字段。

错误统一携带 `error.code` 和 `error.message`：invalid_request、not_found（包含不属于当前账号）、conflict、invalid_action、corrupt_state、storage_unavailable。未来 HTTP 层分别映射 422/404/409/409/500/503，不回显数据库异常。R1 无流式接口。初始化数据库失败同样返回 `storage_unavailable`，不直接抛出底层 SQL 或连接异常。

写入在单事务内完成状态版本更新与回执；用数据库 revision 条件更新处理并发，不依赖进程内锁。同请求并发提交只能成功一次。数据库失败回滚所有变化，不出现“物件已放下但没有回执”。

## 5. 旧数据、迁移与回退

R1 的表使用独立 metadata，仅显式初始化隔离库，不挂到主应用启动。SQLite 每次取用连接时启用并核对外键约束，覆盖已有连接池和重新建立的连接；空间删除时关联回执由数据库级联清理。本阶段仍不提供空间删除接口。测试和复核脚本以临时数据库运行；既有伙伴、聊天、记忆、花园、图片、Demo 与服务均保持可用。

R2 正式接入时编写 Alembic 迁移：先备份并验证恢复，显式建立账号归属后将旧花园转换为私人庭院，保留超限旧存档及旧撤销语义；不能默认把旧数据分给首个登录用户。迁移需有幂等标记，成功核对后才切换路由，切换前后各保留回退入口。现阶段不运行该迁移。
