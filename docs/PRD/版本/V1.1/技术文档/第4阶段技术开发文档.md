## 1. 目标与实施顺序

让伙伴根据当前住处和实际布置提出一项可确认的建议；补齐用户主动再创作所需的独立身份、恢复与额度事件。沿用现有账号、伙伴、场景存档和模型服务，不引入新的平台或部署资源。

| 子步骤 | 实现内容 | 交付边界 |
| --- | --- | --- |
| R4.1 | 场景 Agent 的受约束决策循环、查询工具、提议校验及可恢复执行记录 | 先以隔离适配器验证边界；未接入真实模型的运行器明确标为工程准备 |
| R4.2 | 模型适配、聊天接入、确认／拒绝及刷新恢复 | 沿用当前模型配置；真实契约需在新的明确测试额度内验收，默认聊天不能被未验证的 Agent 替换 |

## 2. 现有能力与复用边界

- `LivingStore` 是生活场景的唯一写入规则，具备版本、幂等回执、照料、撤销与存档兼容能力。
- `scene_bridge` 已统一聊天页与当前生活空间。确认提议使用空间 ID、版本及位置代次检查，不另建第二套花园状态。
- 当前 `detect_scene_action` 是明确句式规则，不冒充自然语言 Agent。真实模型适配未验收前，现有聊天路径继续使用它。
- 生成链路已保存文字特征、角色构思和最终生成依据；同对象重试和纠正副本不等于新的主动再创作。

## 3. R4.1 运行器契约

新增独立服务 `app/scene_agent/runtime.py`，不读取 `.env`，不创建模型客户端，不自动启动后台任务。由宿主注入决策适配器和只读上下文；离线测试传入脚本化适配器，不能把它当成真实模型能力。

### 3.1 状态与身份

每次运行使用服务端生成的 UUID，绑定 owner、伙伴、空间、场景类型、场景版本、位置代次和来源消息 `source_message_id`。启动请求带 UUID 幂等键；相同账号和键重发读取原任务，不再次运行决策。不同输入复用该键产生 `conflict`；R4.2 的 HTTP 层将其映射为 409。上下文只能由验证过归属的宿主构造，不能直接信任客户端字段。

状态为 `running`、`waiting_confirmation`、`completed`、`failed`。最终结果记录回复文本及至多一条动作提议；原始输入与上下文只在本地账号归属的任务记录中保存，不打印到日志。记录 schema 版本、调用数、工具数和安全错误码。

- 每次调用决策适配器前先持久化调用计数。
- 决策输出与工具结果逐步保存，保存失败即停止，不继续调用适配器。
- 中断的 `running` 在显式恢复操作中标为失败，不自动重新消费模型调用；已完成及等待确认的任务直接读取。
- 运行器提供内部 Python 入口；R4.2 的 HTTP 宿主从服务端会话读取 owner，不新增无鉴权入口。

### 3.2 决策输出

只允许以下两种严格 JSON 对象，不接受额外字段：

```json
{"type":"tool","name":"read_scene","arguments":{}}
```

```json
{"type":"finish","reply":"想一起种下一棵小树吗？"}
```

`finish.reply` 为去首尾空白后 1–1000 字。工具名称只能来自下面的白名单；工具参数不接收账号、伙伴、空间或版本，全部由宿主绑定。未知工具、错误类型、超长回复及多余字段均失败关闭，不执行任何场景修改。

### 3.3 工具白名单

| 工具 | 参数 | 返回内容 |
| --- | --- | --- |
| `read_companion` | 空对象 | 本轮宿主提供的伙伴名字与性格，不扫描其他伙伴或用户资料 |
| `read_scene` | 空对象 | 绑定空间的场景名称、真实物件摘要、允许动作和版本 |
| `propose_scene_action` | `action` | 待确认动作；必须在本场景动作白名单内 |

提议前必须查询本轮场景，不可仅依据历史聊天猜测。提议工具成功即进入 `waiting_confirmation`，使用宿主的固定动作说明生成确认文案；不继续调用模型声称动作已执行。运行器没有 `execute`、`delete`、切换住处、付费生成或对外分享工具。

本轮白名单复用现有场景动作：庭院支持种树、花、蘑菇、长椅、水池、营火、萤火虫、小雨及安静；沙漠和林间先支持现有聊天能力“种树”。照料、收纳等仍通过场景按钮操作，后续若扩展自然语言工具，先更新契约和测试。

### 3.4 限额与失败

默认最多 3 次决策、3 次工具、1 项提议。运行总时限是宿主截止时间约束，适配器每次接收剩余秒数，必须设置网络超时；返回超过截止时间的结果不得继续形成提议。本模块不能强制终止任意第三方 Python 函数，因此不宣称它能中断不合作的适配器。

SDK 初始化放在适配器的 `decide` 内，确保初始化失败也能被运行器记录；适配器异常、格式错误、调用次数耗尽或超时均写入失败状态，不把异常原文／堆栈返回给用户，也不自动再跑一次。存储及请求错误使用 `AgentError.as_dict()` 返回统一错误结构，运行中的失败使用已持久化的安全错误码。费用预算继续由外层的真实调用授权和模型适配器约束，调用数上限不等于费用已获授权。

### 3.5 确认、拒绝和过期

R4.1 只持久化待确认提议，不修改 `living_spaces`，不直接改变现有 `SceneProposal`。

R4.2 宿主将提议映射到现有 `SceneProposal`，确认时重新读取账号、伙伴位置、成员关系和最新场景版本，在同一事务中验证、执行并结束提议。刷新恢复不能自动确认。拒绝、版本变化、换场景、退出同住、清空来源消息或删除伙伴均结束提议，失效提议不可复用。

R4.2 已补齐任务记录的删除联动与清理，主服务启动时建表并恢复中断任务。开关关闭时不创建新的 Agent 聊天任务。同步适配器在流工作线程中执行，保持 `done`／`error` 收尾契约。

## 4. 主动再创作设计

入口文案“再创造一个”，先明确将创建新伙伴、保留原伙伴并消耗一次生成额度，再由用户启动。名字修改不走此入口。

使用独立 `creation_id` 和用户级幂等键绑定来源伙伴、确认后的物品描述／特征及新结果，不修改来源对象或复用旧伙伴 ID。重发同一创建读取同一结果，不能再次扣额度；用户明确开始另一轮才分配新标识。

每次主动再创作重新构思名字、性格与形象设计，不能直接复用旧构思当作差异化创作。原图不延长留存，只使用已保存文字依据。旧伙伴的图片、聊天、记忆、场景和当前位置都保留。

额度事件与创建预留绑定，成功结算与失败回退必须幂等。2026-09-21 用户确认每账号初始 5 次，技术失败返还，成功后因不满意再创作仍扣 1 次；具体契约见第 9 节。

## 8. R4.2 接入契约（实现前补充）

本节先于 R4.2 实现补充；随后按用户“一起开发”的指令完成第 9 节再创作与额度，正式开关仍等待真实验证。

- 配置 `SCENE_AGENT_ENABLED=false` 默认关闭。开启时，现有 `POST /characters/{id}/chat` 使用运行器，且必须已有有效生活场景；关闭时保留原流程。现有前端的 `chunk`、`done`、`error` 和 `proposal` 契约不变。
- 请求增加可选 UUID `request_id`。同账号同键绑定同伙伴和原消息，重复请求读取原任务，不能重复保存用户消息、调用模型或发布助手回复。缺省键由服务端分配并通过 `task` 事件返回；客户端希望安全重发时必须复用该键。
- 新增 `GET /characters/{id}/chat/requests/{request_id}`，仅当前账号可读；返回 `running`、`completed`、`failed`，结果及安全错误码。读取和刷新不能触发模型调用。已消费／过期的提议不随旧结果重现。
- 新表 `scene_agent_chats` 保存请求绑定、来源消息、上下文和已发布结果；运行器原表保留计数与决策。清空聊天或删除伙伴时，在同一事务删除两者，迟到结果不得恢复记录。启动恢复中断任务只置失败，不自动调用模型。
- 运行器先持久化，再在同步流工作线程内调用适配器，不在 HTTP 事件循环内阻塞。模型适配沿用当前文本模型，使用既有 OpenAI 兼容接口，不选择新模型；单次请求不自动重试，网络超时使用本轮剩余时间，输出只接受有界严格 JSON。
- 伙伴人设、手动记忆及最近对话以有界上下文数据传入，不允许修改工具白名单。查询工具仍使用宿主绑定的真实空间快照，不采信模型传回的账号／空间标识。
- 发布回复时重新检查来源消息、最新用户消息、账号、位置代次、空间与版本。迟到的旧请求不能撤销新请求的建议；场景发生变化时取消旧建议，返回明确说明。助手消息、建议和任务结果同一事务保存。
- 确认／拒绝复用现有 `SceneProposal` 与 `LivingStore`。读取结果时从实际提议表和最新空间判断是否仍待确认；不得凭运行器的旧 `waiting_confirmation` 恢复已处理提议。
- 测试使用注入决策与 HTTP MockTransport，覆盖输出契约、单次网络请求、鉴权、幂等、确认／拒绝、换场景、删除／清空、重启与 SSE 终止。真实厂商兼容性与质量另行限额验收；通过前主配置保持关闭。

前端同步补充：发送前保存本次 UUID 与消息到当前伙伴的会话存储，网络异常后保留；页面恢复仅查询任务和已保存历史，不自动重发。`running` 时禁用新发送并提供核对按钮；明确完成／失败后结束本次待核对状态。开关关闭且不存在对应 Agent 记录时，查询返回 `untracked`，沿用旧聊天的人工核对逻辑。开启状态下查询不到任务时，只允许用户显式用原 UUID 重发，避免把传输失败当成新创作；已有新草稿不能被恢复结果覆盖。

“继续处理原消息”按钮始终复用原 UUID：已运行的任务只读状态，尚未启动的任务由这次明确点击启动；不自动轮询或重放。

## 9. R4.3 再创作与额度契约（实现前补充）

- 新增账号额度表和生成事件表，账号初始 5 次；仅开启 `GENERATION_QUOTA_ENABLED` 时对新生成预留 1 次。已有伙伴不追溯扣减，默认开关关闭直到联调与真实验证完成。普通生成与再创作走同一额度规则，识别本身不扣伙伴生成额度。
- 预留与生成中伙伴同事务保存；成功保存结果时把事件结算为已消耗；明确技术失败／未完成生成被关闭／重启恢复失败时，返还同一次预留。重复失败处理不多返，重复成功处理不再扣。余额不足先拒绝，不调用模型。删除已成功的伙伴不返还额度；删除生成中伙伴先结束预留。
- `GET /characters/generation-credits` 返回是否启用及当前可用次数；关闭时不展示虚假余额。额度是内测产品规则，不接真实付款或订阅系统。
- `POST /characters/{id}/recreations` 带必填 UUID `request_id`，服务端校验原伙伴归属与生成完成状态，再创建独立对象、伙伴及再创作回执。新对象仅复制已保存的物品描述与特征，不保留或重取原照片、不复制旧构思。旧伙伴、图片、聊天、记忆与场景保持原值。
- `GET /characters/recreation-requests/{request_id}` 按当前账号读取本次任务和结果。重复 POST 同一请求只返回已保存结果或当前状态；同键不同来源报冲突。技术失败后新一轮显式操作使用新请求标识；不能偷偷自动重跑。
- 再创作重新调用角色构思，提示保留物品特征、避开旧名字／性格／形象设计；绘图仍只接收文字。独立身份与独立生成调用可离线验证，真实形象差异与美感仍须样例评分，不能以 mock 占位图证明独特性。
- 前端在伙伴页提供“再创造一个”，先显示消耗 1 次及保留原伙伴，点击确认后请求；等待／中断时先查询回执，完成后进入新伙伴。刷新不自动生成，用户可继续保留原伙伴。

再创作失败的对象不能通过普通生成接口重新启动，需从原伙伴显式创建新请求，避免旧回执被新结果覆盖。照片创建页展示真实额度，额度为 0 时在上传识别前提示；生成接口仍独立校验并原子预留，防止并发超扣。

| 样例 | 验证内容 | 通过条件 |

| 普通陪伴对话一条 | 无布置意图的聊天 | 能正常回复，不强制产生场景建议 |
| 生成建议后换住处／改布置 | 真实结果与宿主版本校验 | 旧建议失效，不写入错误空间 |
| 同一已保存物品主动再创作两次 | 构思、文字驱动绘图及独立身份 | 原伙伴保留；两次独立生成；可辨认原物特征，名字、性格与形象有可感知差异 |
| 完成结果刷新／再次点击恢复 | 真实结果恢复 | 不增加模型调用或重复扣额度 |

每条记录场景、匿名样例编号、实际模型标识、调用次数、耗时、成功／错误码和费用依据；估价与厂商账单分列，不保存密钥。真实独特性由用户对原物辨识、可爱温馨感、名字与性格差异、形象差异分别评分并确认可接受标准，不用离线占位图代替质量结论。失败样例保留原结果，修复后单独记录复验；完整通过后才开启对应功能。

## 12. 全局体验审查修复契约（2026-09-21）

依据：[全局审查报告](../验收证据/阶段4/全局体验审查/全局审查报告.md)。用户同意继续后，先补充本节，再修改代码。本轮属于 R4 修复，不进入 R5，不更换模型；主环境功能开关保持原值。

| 问题 | 实现与验收要求 |
| --- | --- |
| 新伙伴未选住处不能聊天 | Agent 上下文允许明确的“尚未选择住处”；空间标识、类型、版本必须同时为空，物件为空。普通聊天仍持久化、幂等、可恢复。无住处不能产生布置提议，布置意愿提示先选择住处；不自动创建虚构花园。旧运行记录继续可读。 |
| 被拒绝消息阻塞后续发送 | 明确未受理的 HTTP 错误解除待处理标识，保留草稿；断网、超时、服务异常及处理中仍保留原请求。查询 404 时显示核对／继续入口，继续使用同一请求标识，不能偷偷重复生成。 |
| 手机聊天与上传入口过深 | 伙伴页提供聊天／生活切换，手机默认聊天；聊天导航可定位聊天。上传页压缩移动端介绍和装饰，首屏可选择照片，保留限额、隐私及失败恢复说明。 |
| 离开生成页后无法改名 | 伙伴详情有稳定改名入口，1–40 字验证；成功后更新名称，失败保留输入。改名不生成图片、不扣额度。 |
| 验证码重复发送 | 发送成功后按手机号倒计时 60 秒；切换号码、关闭再打开不能绕过当前页面会话的倒计时。429 显示冷却提示。登录仍可在倒计时中提交。 |
| 场景物件重叠／展示割裂 | 保留用户原坐标；普通浏览也能从清单选中被遮挡物件。庭院先做天空、地面与小路的代表视觉，伙伴形象在场景中可见；装饰不冒充已保存物件，三类场景保持差异。 |
| 首页与伙伴展示 | 已登录首页优先收藏与创建入口；扩大伙伴头像、提供放大查看，聊天使用伙伴形象。保持温暖淡紫／淡粉基调及单一登录入口。 |
| 文档陈旧 | V1.1 PRD 更新已确认的自动生成、可选多场景与账号规则；实现进度仍以项目状态为准，历史证据不改写。 |

验证覆盖：无住处聊天／布置请求／选择住处后建议、重复请求与恢复、拒绝后修改消息、未知状态不重复提交、改名及验证码倒计时；完整后端与前端回归、类型检查、Lint、生产构建；隔离账号在桌面与手机走通创建结果→聊天→选住处→布置→刷新。截图和结果写入阶段 4 的“全局体验修复”目录。真实模型质量与 5 秒目标仍待后续约定验证，不用 mock 结果宣称达标。
