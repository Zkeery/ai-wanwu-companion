# 分析构思链路开发与验证报告

2026-09-21。按用户截图表达的流程结构开发；先编写[第3阶段技术开发文档](../../技术文档/第3阶段技术开发文档.md)第 13 节再实施。不据截图断言 Snapplings 的实际底层模型，不新增 Anthropic／Vercel 依赖，沿用当前国内模型配置。

## 1. 最终流程

照片 → 视觉模型同时识别物体、提取特征和构思角色 → 用户确认 → 完整文字设定 → 文生图 → 保存伙伴。

完整文字设定包含名字、性格、开场白及形象设计描述。绘图优先保留照片特征，同时采用设计描述塑造身体、表情、姿态和材质；名字只作称呼。生图请求不包含原照片，原图仍不落盘。

| 情况 | 行为与模型请求 |
| --- | --- |
| 新照片、构思完整、未修改依据 | 视觉分析构思 1 次＋绘图 1 次，共 2 次 |
| 用户修改对象描述／照片特征 | 不用过期构思，按确认后的文字再构思一次，再绘图 |
| 旧识别结果没有构思 | 确认后补构思，再绘图；不重新上传原照片 |
| 绘图失败后手动重试且依据未变 | 复用已持久化构思，只重新绘图，不自动重试 |
| 改名 | 保留图片、性格和原始生成依据，不调用模型 |

正常新照片链路由此前 3 次减为 2 次；这不是实际延迟或成本保证。修改／旧记录兼容分支仍可能总计 3 次。`CHARACTER_BUNDLE_ENABLED=false` 保留旧分拆回退，关闭时不要求视觉构思，也不复用合并构思缓存。

## 2. 数据与失败处理

新增 `objects.character_concept_json`，绑定当前对象描述、特征、版本和构思，不能跨对象／账号复用。完整构思在绘图前提交，绘图失败不丢构思。字段缺失、错误类型、超长等畸形构思拒绝保存；缺少整个构思的旧结果走兼容补充。

保留第 12 节的安全错误分类和明确失败恢复：失败落库后直接回确认页；连接不明时先读取核对。日志不记录模型原文、照片或密钥。

主服务已加载。迁移前无识别／生成任务，备份为 `backend/data/backups/before-photo-concept-20260921-173443.db`。新增列后比对 14 张表的既有列、既有记录，无变化；已有伙伴可继续使用。备份仅本地保留。
