# R3 流程排查与修复报告

日期：2026-09-21。本次针对用户反馈的“流程走不通”检查当前工作区。没有收到具体失败步骤，因此结论基于代码、失败复现测试和隔离浏览器联调；不能据此认定已覆盖用户遇到的全部问题。

## 1. 结论

已复现并修复 5 处衔接问题。单人路径“登录 → 上传识别 → 生成 → 改名 → 聊天 → 三场景布置”在隔离环境跑通。R3 仍未整体验收，完整首版未完成。

| 问题 | 原因与修复 |
| --- | --- |
| 场景选择页点重新加载后一直等待 | 原按钮只清空状态，没有重新触发请求；改为重新加载列表和位置。 |
| 场景详情页出错后重试无效 | 原按钮没有清除错误、也没有重新触发请求；补齐完整重试。 |
| 从收藏链接或直接地址进入已有场景，当前位置未改变 | 原实现只在新建场景时更新位置；已有场景进入也同步位置。增加并发创建冲突后的读取恢复，忽略已离开页面的请求。 |
| 场景操作遇到版本冲突或响应丢失后，连续操作仍失败 | 原页面沿用旧版本；失败后先读取服务端最新状态，不自动重放写入。读取也失败时锁住操作，提供“核对场景”。 |
| 登录验证前恢复上次创建进度 | 原恢复请求与身份校验同时进行；现在身份校验成功后才恢复，登录成功也会重新核对。 |

场景创建成功后即更新本地列表，避免后续设置位置失败时忘记已创建的空间。场景操作增加即时锁，阻止同一轮重复点击提交。

- 修复后：前端 **70/70**；后端 **299/299**（隔离数据库、强制模拟模型）；类型检查、Lint、生产构建通过。
- 浏览器：使用 ego-browser，同一 TaskSpace；临时前端 3022、后端 8022，独立测试数据库和上传目录。没有调用真实模型或发送真实短信。
- 页面实测：测试登录、上传合成 PNG、选对象、生成、改名、聊天收尾；进入家庭庭院种树、照料、收纳、摆出、点击移动、撤销；进入沙漠放遮阴处、进入营地放坐垫。

## 4. 复验方式

打开 [当前前端](http://127.0.0.1:3020)，刷新页面后，从首页单一注册/登录入口进入；当前只使用页面标明的开发验证码。已有伙伴可直接进入“生活场景”，检查切换、种树、照料、收纳、摆出与撤销。进入已有场景后返回选择页，应看到正确的“当前所在”。

自动回归在 `frontend` 运行 `npm test`、`npm run typecheck`、`npm run lint`、`npm run build`；在 `backend` 运行 `.venv/bin/python -m pytest -q`。测试夹具使用独立数据库并覆盖真实模型配置。本次完整浏览器链路用模拟模型，不代表真实模型验收。

## 6. 登录问题补充复验

用户截图确认：手机号以 12 开头，未通过手机号正则校验；发送与提交按钮均禁用，但旧页面没有原因提示。后端实际登录和会话接口均返回 200，因此该截图中的直接断点位于表单校验。

已修复：无效手机号显示明确提示；主按钮固定执行登录，已有验证码无需先点发送；本地配置下提供“填入测试信息”，明确不会发送真实短信；浏览器无法保存登录状态时显示错误，不再假装登录成功。保留现有后端手机号校验与认证协议。

前端新增 4 项回归，完整 74/74，类型检查和 Lint 通过。前三项修复前均失败；补充截图场景验证。浏览器在当前 3020/8020 服务上复现了无效号码提示，再点击“填入测试信息”→“登录”，成功关闭弹窗并进入已登录首页。没有发送真实短信或调用模型。

用户复验：刷新当前页面，打开注册/登录，点击“填入测试信息”，再点击“登录”。若使用自己的手机号，需符合页面格式提示。本地测试入口不代表真实短信已上线。
