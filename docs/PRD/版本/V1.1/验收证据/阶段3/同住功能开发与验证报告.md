# 同住功能开发与验证报告

日期：2026-09-21。先提交此前改动（`3d09dd5`），再编写[第3阶段技术开发文档](../../技术文档/第3阶段技术开发文档.md)第 11 节，之后实施。本轮是 R3 的同住功能增量，不是下一阶段交付。

## 1. 实现结果

场景选择页现可选择独居或同住，三个场景均可创建／复用本账号的共居空间，并添加、移出自己的已生成伙伴。同名伙伴用编号区分。加入成员不自动改变其他伙伴的位置，点击“搬进这个同住空间”后才移动当前伙伴。

场景详情使用明确的空间实例 URL；刷新恢复相同实例，旧类型 URL 优先恢复当前同类型空间。无效实例或已移出的伙伴显示错误，不自动另建独居空间。搬回独居保留共居存档；移出成员不删除伙伴、私人空间或共居物件。

写入期间防止连点；失败只读取核对，不自动重放。部分成功保留服务端结果，核对失败则暂停写入，用户点击“核对居住状态”恢复。离开页面后的迟到响应不会继续搬家或跳转。

未修改后端业务接口、模型配置或数据库结构，未操作用户的真实伙伴数据。原有前端热更新服务 3020 加载本次代码，后端保持 8020。

## 4. 用户验证

打开 http://127.0.0.1:3020 ，登录后从收藏选择已有伙伴，进入“换个地方”→“和我的其他伙伴同住”。在家庭庭院创建或选择同住空间，加入另一个已有伙伴，再点击“搬进这个同住空间”。种一棵树后，让另一伙伴从自己的场景选择页进入同一空间，应看到同一棵树。切回独居再返回，共居布置应仍在。

这些场景与成员操作不调用生成模型。只有照片识别、生成或聊天仍会按当前模型配置调用服务。
