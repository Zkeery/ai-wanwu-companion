# AI万物伙伴 · 架构与功能总览

更新：2026-09-21，已对齐 R5.2 实现。需求以 [V1.1 PRD](PRD/版本/V1.1/PRD.md) 为准，开关、验证与待验项见[项目状态](项目状态.md)。

产品链路：登录 → 自由拍摄或选择水果主题 → 识别与角色构思 → 生成独特伙伴 → 改名、私人收藏、聊天 → 选择庭院、绿洲或营地生活。个人主题工程已实现，公开作品墙与好友小队仍在 V1.1 后续范围。

## 2. 前后端职责

前端使用 Next.js App Router、React、TypeScript，默认端口 3020；负责页面、输入、反馈与请求恢复，通过 API 转发连接 8020 的 FastAPI/Python 后端。后端负责身份归属、输入校验、生成调度、额度、主题匹配、场景规则、持久化和模型调用，生成及聊天用 SSE 返回阶段、结果或错误。

SQLAlchemy/SQLite 保存账号、照片识别信息、伙伴、主题归属、消息、记忆、回执、场景及 Agent 运行记录。当前是本地单实例架构；原照片不落盘，识别文字和生成图片保留，默认数据在 backend/data。密钥只在后端配置与环境中使用。

共享 agent-blueprint 是开发辅助工具，不在产品请求链路中。H1 是独立演示；正式场景 Agent 已有 R4 工程接入，真实模型契约待验，主开关尚未开启。

## 3. 创建、主题与恢复

通常由同一次视觉调用识别照片对象、特征、类别并构思主要对象，再将完整文字设定交给文生图。用户修改描述或使用旧识别结果时可补构思。图片依据对象、照片特征、性格与形象描述生成，不是只按名字合成。

主题来自上传时的选择，持久保存在照片和伙伴上。水果主题只接受识别类别为 fruit 的候选；unknown、非水果或修改对象名后不能沿用旧类别证明。前端停在候选步骤，让用户换对象、换照片或明确自由创作；后端在扣额度与绘图前重复检查。

结果默认私人收藏。断线先查询服务端回执，不自动重复生成。重启时未完成任务标为失败并按规则返还额度，已保存结果可恢复。纠正和再创作保留原伙伴并产生独立身份；改名不重新绘图。

## 4. 生活场景与聊天

伙伴资料、聊天和记忆按伙伴保存；环境按场景实例保存。私人空间属于伙伴，共居空间归账号并关联同账号伙伴。删除伙伴解除自己的成员关系，不删除共居中其他伙伴的环境。

普通树苗约 72 小时有效成长长成，一次照料更新至当前时间起 24 小时，连点不叠加。缺照料或收纳时暂停、不死亡；物件有稳定 ID 和场景坐标，刷新可恢复。

主环境关闭 Agent 时沿用确定性的提议规则；开启后可读取场景并提出白名单动作。两条路径都要确认、权限与版本检查；场景切换和位置代次防止迟到回复改错地方。伙伴口头说“种好了”不会改变环境。手动布置不调用模型，雨声由用户主动开启，离开页面停止。

## 5. 后续社交链路

R5.2：作者预览并主动发布后，作品墙展示角色图、名字、简介、主题和作者展示名；撤回不删除私人伙伴，不公开原图、聊天、记忆或手机号。

R5.3：小队绑定一个主题，邀请需确认加入；作品由成员主动提交，可撤回／退出，发起者可撤销邀请或解散。小队提交与公开发布独立。两个批次仍在同一个 V1.1 首版内。
