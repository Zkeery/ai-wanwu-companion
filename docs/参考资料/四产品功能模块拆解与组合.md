# 四产品功能模块拆解与组合方案

日期：2026-09-18（本次重新用浏览器逐个打开确认；Sandspiel 元素互动与 Patatap 视听机制为本次新增的一手证据）。
Snapplings 与 Chatchuu 的早期拆解见 [Snapplings-Chatchuu-deconstruction.html](Snapplings-Chatchuu-deconstruction.html)，本文件在其基础上补齐四款产品的统一功能模块视图与组合结论。

## 一、四个产品拆解

### 1. Snapplings（snapplings.com）

定位：拍照生成"可收藏角色"，**明确没有聊天**。

| 模块 | 观察 | 对本产品的价值 |
| --- | --- | --- |
| 拍照/选图入口 | 相机拍摄、相册选图、拖拽；纯浏览器、免注册 | ✅ 要：照片是"个人关联"的来源 |
| AI 角色生成 | "AI turns it into a one-of-a-kind creature" | ✅ 要：物品 → 专属角色 |
| 卡片化 | 图鉴每张卡含名称、稀有度(Rare/Epic/Legendary)、类型(Spirit/Construct/Flora/Stone/Volt) | ⚠️ 部分：保留名称+类型标签，稀有度后做 |
| 收藏柜 Vault / 公共图鉴 Showcase | 个人收藏 + 公开作品墙 | ✅ 收藏柜要；公共图鉴首版不做 |
| 游戏化 | 每日任务(10/15)、货币 Glitter、融合、交易赠送、对战 SnapArena、组队 SnapSide FC、周边 | ❌ 首版全缓 |
| 隐私口径 | "照片只用一次，之后丢弃"；无聊天、无 feed、无关注 | ✅ 借鉴"原图临时处理" |

**结论**：解决"获得一个角色 + 收集获得感"，但拿到角色后没有后续关系。

### 2. Chatchuu（App Store id6775716440）

定位：照片识别对象并**与其聊天**，但没有收藏归属。

| 模块 | 观察 | 对本产品的价值 |
| --- | --- | --- |
| 拍照/相册 | 拍一张或从相册选 | ✅ 要 |
| AI 对象识别 | "identify the elements in the image"（多元素） | ✅ 要：先识别再让用户确认/选择 |
| 选择/切换对象 | "select anything, switch anytime" | ✅ 要：降低识别出错的影响 |
| 文字聊天 | 和宠物/植物/餐食/玩具/画作聊天 | ✅ 要：主线 |
| 角色标签 | 截图呈现角色名 + 对象标签 | ✅ 要：角色身份来自对象 |
| Pro 订阅 | 部分功能需订阅 | ❌ 先免费验证 |
| 隐私口径 | 商店"Data Not Collected"与隐私页"数据传 AI 服务商"口径矛盾 | ⚠️ 不照抄，按自有数据规则设计 |

**结论**：解决"和对象聊天"，但角色无收藏、无连续性归属、无场景。

### 3. Sandspiel（sandspiel.club）

定位：落沙沙盒，自由布置 + 元素互动 + 平静探索。**无 AI、无角色、无声音。**

完整 20 元素（本次从 /info/ 页确认）：

> Wind / Empty / Wall(坚不可摧) / Sand(沉入水) / Water(灭火) / Stone(成拱、受压变沙) / Ice(冻水、滑) / Gas(易燃) / Cloner(复制首个接触元素) / Mite(吃木与植物、爱灰尘、冰上打滑) / Wood(坚固但可降解) / Plant(喜湿) / Fungus(蔓延一切) / Seed(在沙/植物/真菌上生长) / Fire(热) / Lava(易燃且重) / Acid(腐蚀) / Dust(漂亮但易爆) / Oil(燃烧产烟) / Rocket(爆炸成首个接触元素的副本)

| 模块 | 对本产品的价值 |
| --- | --- |
| 元素调色板 + 粒子物理 | ⚠️ 只借鉴"元素互动"创意，不做完整粒子模拟 |
| 平静探索、无目标 | ✅ 借鉴放松、低压力调性 |
| Reset / Info 说明 | ✅ 借鉴可撤销 + 规则可见 |

**结论**：提供"一起动手布置"的场景感，但无角色、无 AI、无声音。

### 4. Patatap（patatap.com）

定位：按键触发"声音 + 动画"的视听联觉玩具。**无 AI、无角色、无持久化。**

| 模块 | 观察 | 对本产品的价值 |
| --- | --- | --- |
| 键盘/触碰触发 | "Press any key, A to Z or spacebar" | ✅ 要：触碰即反馈的低门槛愉悦 |
| 声音 + 几何动画联觉 | 每键 = 音色 + 形状动画（Lullatone 音乐） | ⚠️ 部分：触发式音效要；实时音乐生成不要 |
| 无目标纯玩 | 无任何任务 | ✅ 借鉴"不想打字时也能玩" |
| 移动端/周边/姊妹项目 | Typatone、Curaturae | ❌ 不需要 |

**结论**：提供即时感官愉悦，但无角色、无 AI、无保存。

## 二、组合逻辑

四款产品是"同一个物品"的四段旅程：

```
Snapplings      Chatchuu        Sandspiel        Patatap
   ↓               ↓                ↓                ↓
获得一个角色   和它建立关系   和它一起布置场景  和它一起玩/表达
(生成+收藏)    (对话+记忆)    (元素互动)       (声画反馈)
```

各自缺的正好是对方有的：Snapplings 有角色无关系；Chatchuu 有关系无归属；Sandspiel 有场景无角色与 AI；Patatap 有表达无角色无保存。

组合不是拼四个 app，而是**用同一个角色把四段旅程串起来**：

> 把一件有意义的物品，变成能持续陪伴你的 AI 伙伴；你可以收藏它、和它聊天、一起布置一个会发声的小世界。

"同一个角色"是唯一粘合剂：外形、名字、人设、说话方式、场景里的表现，全部来自用户确认过的那件物品。这是四款竞品都没有做、而本产品能成立的核心。

## 三、组合方案（已按推荐确认）

### 首版主线

| 来源 | 借用模块 | 裁剪 |
| --- | --- | --- |
| Snapplings | 拍照 → 生成专属角色 | 去掉稀有度/每日任务/Glitter/对战/交易 |
| Chatchuu | 识别 → 确认对象 → 选择 → 文字聊天 | 保留为"关系"主线 |
| Snapplings+Chatchuu | 收藏柜 + 连续会话 | 收藏角色、下次打开还是同一个它 |
| Sandspiel | 元素互动场景 | 预置 1-2 个小场景 + 少量元素 + 角色反馈，不做完整粒子物理 |
| Patatap | 触碰即声画反馈 | 触发式音效 + 氛围音色，不做实时音乐生成/MIDI |

### 首版明确缓做

- 稀有度经济、融合、交易、对战、排行榜、周边、每日任务（Snapplings 整套游戏化）
- 完整 20 元素自由沙盒、开放生态模拟（Sandspiel 重工程）
- 实时音乐生成、完整音色库、MIDI（Patatap 重工程且贵）
- Pro 订阅、语音、分享卡

### 设计底线

1. 同一个角色贯穿一切：图片、人设、聊天语气、场景反馈共用同一份角色设定。
2. AI 职责边界：AI 负责理解、创作、表达（识别物品、生成角色、回应聊天、把"下点小雨"转成受控操作）；即时粒子/声音/触碰动画由确定性交互系统负责，不能每次划动都等模型。

### 风险提示

- 四合一最大的坑是做成大杂烩。主轴必须唯一：伙伴关系（角色+聊天）为主，声景为共同活动，声画反馈为调味。
- Sandspiel 粒子物理与 Patatap 实时音频"看起来轻、实现很重"，首版必须裁剪。

## 四、本次确认的决策（按推荐）

| 编号 | 决策 | 结论 |
| --- | --- | --- |
| Q1 | 产品主轴 | 伙伴关系为主，声景为共同活动，声画反馈为调味 |
| Q2 | 首版输入对象 | 物品 + 植物；真人/宠物暂缓 |
| Q3 | 声景互动深度 | 预置 1-2 个小场景 + 少量元素 + 角色反馈 |
| Q4 | 对话改变场景 | 首版做 2-3 个受控操作（如小雨/安静/种树），带确认/撤销 |
| Q5 | 声音方案 | 触发式音效 + 少量氛围音色，不做实时音乐生成 |
