# 资金证明更新接入

当前交付为内部快照消费者，不包含未知的官方财务HTTP适配器。
三个`.example`文件没有安装、启用或授权任何云权限。配置默认关闭；不得直接将审核项改成true来绕过官方接口确认。

## 尚缺的外部事实

官方工单F4NSY8须明确可用余额、完整未出账/未结算责任、数据截止时间、查询费用、最小只读权限及精确字段。
已有token/次数接口不能产生本文件要求的资金证明。获得事实后才能实现对应官方响应适配器；未知字段不能补0，模拟数据不能用于真实任务。

## 已实现的消费者

每个唯一新批次目录0700，以下文件0600：

- `funding-source.json`：采用本目录关闭的示例，绑定同一账户及新批准编号；只接受已审核、零查询费、权限已确认的源合同。
- `funding-input.json`：独立授权的官方源适配器原子发布的内部标准化快照。消费者不会联网采集，也不会使用登录cookie或推理Key查询财务。
- `evidence.json`：给受限生活读取的证明，写入时保持源时间。
- `funding-refresh-state.json`：准备中或停止均阻断读取；ready时还核对证明字节摘要，防止未完成发布或篡改。
- `funding-record-*`：每轮私有收据，保留前份证明、当前源快照和结果。不自动清理旧记录。

`funding-input.json`的内部规范如下，**这是字段说明，不是有效资金证明**：

```text
schema_version: 1
source_type: official_api 或 official_console
observed_at: 官方原始快照时间，整数Unix秒
covers_through: 已涵盖责任的截止时间，必须不早于observed_at且不晚于现在
includes_unbilled: true（必须由官方事实证实）
includes_unsettled: true（必须由官方事实证实）
evidence: 同现有trial_admission契约的private_life和shared_life
```

两组必须引用相同完整账户快照，余额扣除完整待扣至少覆盖6.8736元名义预留；总任务上限仍为7元。精确模型、报价、在售状态与源时间都必须合规；消费者不刷新源时间或生成余额。当前仅接两组生活证明，不处理语音现金账单核销。

## 操作边界

默认CLI只读，不产生目录、账本、模型请求、云查询或任务：

```sh
backend/.venv/bin/python backend/scripts/accounting_proof_refresh.py --directory /ABSOLUTE/PRIVATE/NEW-BATCH
```

显式`refresh`才写入本地证明与收据。首次错误/未知会锁存停止；后续周期返回stopped，不重新读取源或自动恢复，已停止的模型TrialGate始终不会重开。有效证明也不是启动许可，仍需既有批准、观察、凭证绑定及其他启动条件。

生产读取与`life_acceptance readiness/prepare-approved`均检查发布状态。没有更新器状态的历史人工证明保留旧校验兼容；有状态的批次不可通过旧raw evidence绕开停止。

只有官方适配器、费用/权限及配置经过确认后，才可将批次路径和既有运行用户填入service示例，并另行部署。消费者单元禁止网络；未来官方采集器须单独审核，不能扩大此单元权限。timer示例不是当前正在运行的自动核账。

写证明的状态顺序为updating→归档/校验→发布证明→ready。进程在任意中间点退出会保持阻断；不自动抹去失败。恢复须人工核对并采用新的批准/批次，不通过删除guard文件恢复旧批次。

显式加入`funding-source.json`后，即使首次尚未发布、或有人移除了状态文件，生活读取也会保持阻断，不回退到旧人工证明路径。
